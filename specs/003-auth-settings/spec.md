# 认证设置（Auth Settings）能力模块

## 1. 概述

认证设置能力模块负责管理系统中的认证配置，包括登录方式的启用与禁用、注册功能的开关控制、第三方认证提供商的配置等。该模块为 AgentX 平台提供灵活的认证策略配置能力，支持多认证方式的动态管理和运行时控制。

### 1.1 核心价值

- **灵活配置**：支持管理员动态配置系统的认证方式，无需修改代码
- **多认证方式**：支持普通登录、GitHub 登录、敲鸭登录（社区登录）等多种登录方式
- **注册控制**：提供用户注册功能的开关控制，可根据业务需要开启或关闭注册
- **提供商管理**：支持第三方认证提供商的配置，便于扩展新的认证方式
- **配置持久化**：所有配置持久化存储，保证配置的可靠性和一致性

### 1.2 适用场景

- 系统管理员需要启用或禁用特定的登录方式
- 需要根据业务场景控制用户注册开关
- 集成第三方认证服务时需要配置认证提供商
- 前端应用需要获取当前可用的认证方式列表
- 需要动态调整认证功能的显示顺序

## 2. 功能能力

### 2.1 多认证方式配置管理

#### 2.1.1 功能描述

支持配置多种登录方式，系统内置支持的登录方式包括：

- **普通登录（NORMAL_LOGIN）**：传统的用户名密码登录方式
- **GitHub 登录（GITHUB_LOGIN）**：基于 GitHub OAuth 的第三方登录
- **敲鸭登录（COMMUNITY_LOGIN）**：基于社区认证系统的第三方登录

每种登录方式都可以独立配置其启用状态、显示顺序和功能描述。

#### 2.1.2 配置属性

- **启用状态（enabled）**：控制登录方式是否在前端显示和可用
- **功能名称（featureName）**：登录方式在前端显示的名称
- **显示顺序（displayOrder）**：控制在登录页面的显示顺序
- **功能描述（description）**：登录方式的详细说明
- **配置数据（configData）**：存储登录方式的扩展配置信息

#### 2.1.3 使用场景

**场景 1：启用/禁用登录方式**

系统管理员根据业务需要，决定启用或禁用某些登录方式。例如，在特定活动期间仅启用 GitHub 登录以鼓励用户使用 GitHub 账号。

**场景 2：调整登录方式显示顺序**

为了提升用户体验，管理员可以调整登录方式在登录页面的显示顺序，将常用的登录方式放在更突出的位置。

**场景 3：配置登录方式参数**

某些登录方式可能需要额外的配置参数，如 GitHub 登录的 Client ID、Client Secret 等，这些参数存储在 configData 字段中。

### 2.2 启用状态管理

#### 2.2.1 功能描述

提供一键切换认证功能启用状态的功能，支持对单个认证功能的启用/禁用操作，也支持查询多个认证功能的启用状态。

#### 2.2.2 操作方式

- **开关切换**：通过 API 调用切换认证功能的启用状态
- **批量查询**：获取指定类型的所有认证功能及其启用状态
- **状态检查**：快速判断某个认证功能是否启用

#### 2.2.3 使用场景

**场景 1：临时禁用某个登录方式**

当某个登录方式出现问题时，管理员可以快速禁用该登录方式，保证系统的正常运行。

**场景 2：根据业务规则动态调整**

系统可以根据业务规则自动调整认证功能的启用状态，例如在维护期间禁用注册功能。

**场景 3：前端动态渲染**

前端应用根据返回的启用状态动态渲染登录界面，只显示启用的登录方式。

### 2.3 注册功能开关

#### 2.3.1 功能描述

独立的用户注册功能开关，控制用户注册功能是否可用。该开关独立于登录方式配置，可以单独管理。

#### 2.3.2 配置项

- **USER_REGISTER**：用户注册功能键
- **启用状态（enabled）**：控制注册功能是否可用

#### 2.3.3 使用场景

**场景 1：封闭式测试**

系统处于封闭式测试阶段时，可以关闭注册功能，仅允许已注册用户登录。

**场景 2：邀请注册**

可以通过关闭公共注册，改为基于邀请码的方式控制用户注册。

**场景 3：注册审核**

通过关闭公共注册，改用人工审核的方式控制用户注册。

### 2.4 提供商配置映射

#### 2.4.1 功能描述

将认证功能键（featureKey）映射到对应的 SSO 提供商（provider），支持多种第三方认证提供商。

#### 2.4.2 支持的提供商

- **GITHUB**：GitHub OAuth 认证
- **COMMUNITY**：敲鸭社区认证
- **GOOGLE**：Google OAuth 认证（预留）
- **WECHAT**：微信认证（预留）

#### 2.4.3 映射关系

| 功能键 | 提供商 | 说明 |
|--------|--------|------|
| GITHUB_LOGIN | GITHUB | GitHub 登录对应的 SSO 提供商 |
| COMMUNITY_LOGIN | COMMUNITY | 敲鸭登录对应的 SSO 提供商 |

#### 2.4.4 使用场景

**场景 1：第三方登录集成**

当用户选择 GitHub 登录时，系统通过映射关系获取 GITHUB 提供商，并调用相应的 SSO 服务进行认证。

**场景 2：扩展新的认证提供商**

当需要支持新的认证提供商时，只需在 SsoProvider 枚举中添加新的提供商，并在映射关系中配置即可。

## 3. 使用场景

### 3.1 系统初始化

**场景描述**：系统首次部署时，需要初始化认证配置。

**操作流程**：
1. 创建普通登录功能配置，设置默认启用状态
2. 创建 GitHub 登录功能配置，设置默认禁用状态
3. 创建用户注册功能配置，设置默认启用状态
4. 配置各功能的显示顺序

**预期结果**：系统具备基础的认证配置，管理员可以根据实际需要进行调整。

### 3.2 日常运营管理

**场景描述**：管理员在日常运营中需要调整认证配置。

**操作流程**：
1. 管理员登录后台管理系统
2. 进入认证设置页面
3. 查看当前所有认证配置及其状态
4. 根据业务需要调整认证功能的启用状态
5. 保存配置变更

**预期结果**：认证配置变更立即生效，前端登录界面根据最新配置渲染。

### 3.3 第三方认证集成

**场景描述**：需要集成新的第三方认证方式。

**操作流程**：
1. 在 SsoProvider 枚举中添加新的提供商
2. 创建对应的认证功能配置
3. 配置提供商的认证参数（如 Client ID、Client Secret 等）
4. 启用该认证功能
5. 测试认证流程

**预期结果**：用户可以使用新添加的第三方认证方式登录系统。

### 3.4 前端应用请求认证配置

**场景描述**：前端应用需要获取当前可用的认证配置以渲染登录界面。

**操作流程**：
1. 前端应用调用获取认证配置 API
2. 系统查询所有启用的登录方式和注册状态
3. 返回认证配置数据
4. 前端根据配置渲染登录界面

**预期结果**：前端展示正确的认证方式和注册入口。

### 3.5 安全策略调整

**场景描述**：根据安全策略临时调整认证配置。

**操作流程**：
1. 安全团队发现某个认证方式存在安全风险
2. 管理员快速禁用该认证方式
3. 发布公告通知用户使用其他登录方式
4. 问题解决后重新启用该认证方式

**预期结果**：快速响应安全事件，保障系统安全。

## 4. 功能特性

### 4.1 灵活的配置存储

- **JSON 格式存储**：扩展配置数据使用 JSON 格式存储，支持复杂的配置结构
- **类型安全**：使用 MyBatis-Plus 的 TypeHandler 进行类型转换
- **动态扩展**：可以灵活添加新的配置字段，无需修改数据库表结构

### 4.2 统一的功能管理

- **功能类型分类**：通过 featureType 将认证功能分为登录和注册两大类
- **功能键标识**：使用 featureKey 唯一标识每个认证功能
- **统一的 CRUD 操作**：提供标准的增删改查接口，便于管理和扩展

### 4.3 前端友好的数据结构

- **DTO 转换**：提供专门的 DTO 用于前端数据交互
- **简化的登录方式信息**：返回登录方式时仅返回必要的信息（enabled, name, provider）
- **注册状态独立返回**：注册启用状态独立返回，便于前端处理

### 4.4 配置变更即时生效

- **实时更新**：配置变更后立即生效，无需重启系统
- **缓存感知**：支持缓存机制，提高查询性能
- **事务一致性**：配置变更在事务中完成，保证数据一致性

### 4.5 扩展性
### 4.5 扩展性设计

- **枚举驱动**：使用枚举定义功能键和提供商，便于维护和扩展
- **工厂模式**：提供商服务使用工厂模式，便于添加新的提供商
- **策略模式**：不同认证方式可以有不同的验证策略

## 5. 非功能需求

### 5.1 性能要求

- 查询认证配置响应时间 < 100ms
- 支持配置缓存，减少数据库查询
- 支持并发访问，保证多用户同时操作的稳定性

### 5.2 安全要求

- 配置管理需要管理员权限
- 敏感配置数据加密存储
- 操作日志记录，便于审计

### 5.3 可靠性要求

- 配置数据持久化存储，保证数据不丢失
- 支持配置备份和恢复
- 异常情况下的默认配置机制

### 5.4 可维护性要求

- 清晰的配置数据结构
- 完善的日志记录
- 详细的错误提示信息

## 6. 约束与限制

### 6.1 功能键唯一性

- 每个 featureKey 必须唯一
- 不允许重复创建相同 featureKey 的配置

### 6.2 提供商映射

- 只有支持的提供商才能被映射
- 提供商必须预先在系统中注册

### 6.3 配置数据格式

- configData 必须是有效的 JSON 格式
- 配置参数需要符合对应的验证规则

## 7. 依赖关系

### 7.1 内部依赖

- 依赖 SSO 模块进行第三方认证
- 依赖用户模块进行登录和注册操作

### 7.2 外部依赖

- 依赖第三方认证提供商的 API（如 GitHub OAuth）
- 依赖数据库存储配置数据

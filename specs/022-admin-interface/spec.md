# 管理后台（Admin Interface）

## 概述

管理后台模块提供官方服务商和官方工具的管理能力，支持后台管理员对官方资源进行创建、修改、审核和权限控制等功能。

## 功能需求

### 1. 官方服务商管理

**描述**：管理员可以创建和管理官方 LLM 服务商，所有用户均可使用官方服务商。

**功能**：
- **创建官方服务商**：创建新的官方服务商，标记为 isOfficial=true
- **修改服务商配置**：更新官方服务商的 API 密钥、配置参数等
- **设置管理员权限**：将服务商标记为管理员级别（setAdmin()）
- **密钥掩码处理**：修改服务商时，支持传入密钥掩码保留原有密钥

**要求**：
- 官方服务商对所有用户可见和可用
- 支持密钥的加密存储和安全传输
- 修改日志记录，追踪变更操作

### 2. 官方工具审核

**描述**：管理员可以审核用户发布的工具，审核通过后工具发布为官方工具。

**审核流程**：
1. 用户提交工具发布申请
2. 工具进入待审核状态
3. 管理员审核工具内容、接口、文档等
4. 审核通过后，工具标记为官方工具并发布

**审核内容**：
- 工具名称和描述
- 工具接口定义
- 工具文档
- 安全性检查
- 合规性检查

**要求**：
- 支持通过/拒绝审核
- 拒绝时提供审核意见
- 审核记录可追溯

### 3. 后台权限控制

**描述**：只有拥有管理员权限的用户才能执行管理后台的操作。

**权限要求**：
- 创建/修改官方服务商：需要 ADMIN 角色
- 审核/管理工具：需要 AUDITOR 或 ADMIN 角色
- 查看官方资源：所有用户均可
- 管理员操作需要绑定到操作用户
- 敏感操作（删除、批量审核、权限变更）需要 SUPER_ADMIN 角色

**实现方式**：
- 基于角色的访问控制（RBAC），详见 RBAC 模型章节
- 操作审计日志，支持哈希链防篡改
- 操作权限验证，支持细粒度权限（资源：操作：条件）
- 敏感操作二次确认（TOTP 或邮箱验证）

### 4. 管理员服务分层

**描述**：管理后台服务按照领域进行分层，职责清晰。

**服务划分**：
- **AdminLLMAppService**：官方 LLM 服务商管理
- **AdminToolAppService**：官方工具审核和管理

**职责**：
- 应用层服务，协调领域层和接口层
- 处理管理后台的业务逻辑
- 权限验证和操作审计
- DTO 与实体转换

### 5. 官方资源查询

**描述**：支持查询和展示官方服务商和官方工具。

**查询功能**：
- 查询所有官方服务商列表
- 按类型、状态过滤服务商
- 查询官方工具列表
- 按审核状态、类型过滤工具

**要求**：
- 分页查询支持
- 排序支持
- 高性能查询

## 技术约束

- **部署形态**：独立 FastAPI 应用，路由前缀 `/admin`，与用户服务共享数据库但逻辑隔离
- **前端框架**：React Admin + Ant Design Pro（暗色主题支持）
- **后端框架**：FastAPI + SQLAlchemy + Redis
- **认证方式**：JWT Token（有效期 2 小时）+ Refresh Token（有效期 7 天）
- **双因素认证**：敏感操作强制 TOTP（Google Authenticator 兼容）
- **遵循领域驱动设计（DDD）**
- **支持细粒度权限控制**
- **审计日志完整记录**

## 性能要求

- 管理员操作响应时间 < 500ms（P95）
- 资源查询响应时间 < 200ms（P95）
- 审计日志查询响应时间 < 1s（百万级数据，带全文搜索）
- 支持并发管理员数 ≥ 50（同时在线）
- 支持批量操作和批量审核（单次上限 100 条）
- 权限验证延迟 < 50ms（缓存命中）
- 高频查询（如日志分页）使用游标分页 + 覆盖索引，避免 N+1 查询

## 安全要求

- **强制权限验证**：所有管理操作需经过 RBAC 验证
- **敏感信息脱敏显示**：
  - API Key：显示前 6 位 + `***` + 后 4 位（例：`sk-proj***abcd`）
  - 密钥在数据库使用 AES-256-GCM 加密，密钥与应用配置分离
  - 前后端双重脱敏：后端返回掩码数据，前端不展示完整密钥
- **操作审计日志**：
  - 所有管理操作记录审计日志（包含操作人、时间、IP、操作类型、资源 ID、变更详情）
  - 审计日志使用 append-only 表结构，禁止 UPDATE/DELETE 操作
  - 日志哈希链：每条日志包含上一条日志的 SHA-256 哈希值，防止篡改
  - 日志归档策略：热数据（90 天）存 PostgreSQL，冷数据（>90 天）自动迁移到 S3
- **防止越权操作**：数据库层面添加 admin_id 条件，确保数据安全
- **支持操作回滚**：
  - 单条记录回滚：支持恢复到上一版本（使用版本号或时间戳）
  - 批量操作回滚：事务边界内失败则全部回滚
- **双因素认证**：
  - 敏感操作（删除、批量审核、权限变更）强制 TOTP 验证
  - 登录异常检测（异地 IP、新设备）触发二次验证
- **IP 白名单**：支持限制管理员登录 IP 范围（可选）

## 合规要求

- **工具审核需记录审核意见**：审核意见 JSON 格式存储，包含审核人、审核时间、审核项评分、拒绝原因
- **审核流程可追溯**：审核历史永久保存，支持导出 PDF 报告
- **敏感操作需要二次确认**：删除操作需 TOTP 或邮箱验证码确认
- **符合相关法律法规**：
  - 数据保留周期：审计日志至少保留 2 年（符合网络安全法要求）
  - 个人信息保护：管理员敏感信息（手机号、邮箱）加密存储
  - 日志不可篡改：使用 append-only + 哈希链技术
  - 导出支持：支持导出 CSV/Excel/PDF 格式审计报告

## 可扩展性

- **新增资源类型钩子**：
  - 定义 `AdminResourceType` 枚举，支持动态注册新资源类型
  - 审核容器复用 007-tool-integration 和 010-agent-management 的状态机引擎
  - 审核意见模板支持自定义扩展（JSON Schema 验证）
- **批量操作扩展**：
  - 批量大小上限：100 条/次
  - 批量失败回滚：事务边界内原子性操作
  - 批量进度追踪：异步任务 ID + WebSocket 实时推送

## 与其他模块的边界

- **与 007-tool-integration 的关系**：
  - 007 定义工具接入流程和审核容器
  - 本模块复用 007 的审核状态机和容器部署逻辑
  - 007 的 `MANUAL_REVIEW` 状态由本模块的管理员执行审核
- **与 010-agent-management 的关系**：
  - 010 定义 Agent 发布审核流程
  - 本模块复用 010 的审核容器和状态机
  - Agent 审核和工具审核共用同一套审核容器基础设施
- **与 001-user-management 的关系**：
  - 管理员账户复用 user 表，通过 `is_admin` 字段和 `admin_users` 扩展表区分
  - 避免数据冗余，管理员首先是用户

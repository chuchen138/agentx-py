# RAG 管理能力模块 - 需求规格说明

## 概述

RAG（Retrieval-Augmented Generation）管理模块是 AgentX 平台的核心能力之一，提供从知识库构建到智能检索的完整解决方案。该模块支持用户上传多种格式的文档，自动进行OCR识别、文本提取、向量化和存储，并提供高效的混合检索能力，为 AI Agent 提供精准的知识增强。

## 核心能力

### 1. 知识库构建

#### 1.1 数据集管理
- 支持创建和管理多个独立的RAG数据集
- 每个数据集可以包含多个文档文件
- 支持数据集的版本管理和多版本共存
- 提供数据集统计信息（文档数量、文档单元数量等）

#### 1.2 文档上传与处理
**支持的文档格式：**
- PDF文件（支持多页文档）
- Word文档（.doc, .docx）
- 纯文本文件（.txt）
- Markdown文件（.md）

**文档处理流程：**
1. 文件上传到对象存储
2. 自动识别文档类型并提取文本内容
3. PDF/图片文件进行OCR识别
4. 文档内容分页/分段处理
5. 生成文档单元（DocumentUnit）并持久化
6. 文档单元向量化并存储到向量数据库

#### 1.3 文档单元管理
- 每个文档被拆分为多个文档单元（按页或段落）
- 支持手动编辑文档单元内容
- 支持重新向量化指定文档单元
- 记录每个文档单元的OCR状态和向量化状态

### 2. 向量检索

#### 2.1 向量化存储
- 支持多种Embedding模型配置
- 自动批量向量化文档单元
- 向量数据存储在向量数据库中
- 支持向量数据的增删改查操作

#### 2.2 向量相似度检索
- 基于余弦相似度的向量检索
- 支持相似度阈值过滤
- 支持最大返回结果数配置
- 支持多个数据集的联合检索
- 检索结果包含相似度分数

### 3. 混合检索

#### 3.1 检索类型
系统支持三种检索模式：
- **向量检索（VECTOR）**：基于语义相似度的向量检索
- **关键词检索（KEYWORD）**：基于关键词匹配的传统检索
- **混合检索（HYBRID）**：结合向量和关键词检索，使用RRF融合算法

#### 3.2 RRF融合算法
- 使用Reciprocal Rank Fusion算法融合多种检索结果
- 支持融合参数调优（k值配置）
- 自动去除重复结果
- 综合语义和关键词匹配优势

#### 3.3 重排序（Rerank）
- 支持对检索结果进行二次重排序
- 提高检索结果的精确度
- 可选启用/禁用重排序

#### 3.4 HyDE技术
- 支持Hypothetical Document Embeddings技术
- 生成假设性文档提升向量检索效果
- 提升对复杂查询的理解能力

### 4. 文档处理状态机

#### 4.1 处理状态
文档处理包含以下状态：
- **已上传（UPLOADED）**：文件已上传，等待开始处理
- **OCR处理中（OCR_PROCESSING）**：正在进行OCR识别
- **OCR处理完成（OCR_COMPLETED）**：OCR识别完成，等待向量化
- **向量化处理中（EMBEDDING_PROCESSING）**：正在进行向量化
- **处理完成（COMPLETED）**：全部处理完成
- **OCR处理失败（OCR_FAILED）**：OCR识别失败
- **向量化失败（EMBEDDING_FAILED）**：向量化失败

#### 4.2 状态转换
支持状态的有序转换和失败重试：
- 失败状态可以重新触发处理
- 状态转换遵循预定义的事件驱动机制
- 支持失败原因记录和查询

### 5. RAG版本与发布

#### 5.1 版本管理
- 每个数据集维护独立的版本历史
- 版本号遵循语义化版本规范（如 1.0.0）
- 每个版本记录包含的所有文件和文档单元快照
- 支持版本间的对比和回滚

#### 5.2 版本发布流程
- 创建新版本后可提交发布申请
- 支持审核机制，需要管理员审核通过
- 发布状态：审核中、已发布、已拒绝、已下架
- 支持批量审核多个版本

#### 5.3 RAG市场
- 发布的版本可在RAG市场中展示
- 支持其他用户浏览和安装
- 支持按类别、评分等条件筛选
- 提供版本信息和使用说明

### 6. RAG搜索与对话

#### 6.1 检索配置
- 支持灵活的检索参数配置
  - 检索类型选择（向量/关键词/混合）
  - 最大返回结果数
  - 最小相似度阈值
  - 是否启用重排序
  - 候选结果倍数
- 支持多数据集联合检索

#### 6.2 流式检索对话
- 支持流式输出检索结果
- 提供实时检索进度反馈
- 支持在对话中持续检索和响应
- 结合检索结果进行增强生成

#### 6.3 检索结果展示
- 展示检索到的相关文档内容
- 显示相似度分数和来源信息
- 支持结果过滤和排序
- 支持预览文档完整内容

#### 6.4 示例检索请求和响应
**检索请求示例：**
```json
{
  "query": "如何使用 Python 连接 PostgreSQL 数据库",
  "dataset_ids": ["dataset_001", "dataset_002"],
  "search_type": "HYBRID",
  "top_k": 10,
  "similarity_threshold": 0.7,
  "use_rerank": true,
  "rerank_top_k": 5,
  "use_hyde": false
}
```

**检索响应示例：**
```json
{
  "results": [
    {
      "document_unit_id": "unit_123",
      "content": "使用 psycopg2 库连接 PostgreSQL...",
      "similarity_score": 0.92,
      "metadata": {
        "file_name": "Python 数据库编程.pdf",
        "page_number": 45,
        "dataset_name": "技术文档"
      }
    },
    {
      "document_unit_id": "unit_456",
      "content": "SQLAlchemy ORM 使用指南...",
      "similarity_score": 0.88,
      "metadata": {
        "file_name": "SQLAlchemy 教程.md",
        "chunk_index": 12,
        "dataset_name": "技术文档"
      }
    }
  ],
  "total_count": 2,
  "search_time_ms": 234
}
```

## 使用场景

### 场景1：企业知识库构建

**需求描述：**
企业需要将内部文档（技术文档、产品手册、FAQ等）导入系统，构建企业专属的知识库，供AI Agent回答员工问题。

**使用流程：**
1. 创建企业专属RAG数据集
2. 批量上传PDF、Word、Markdown格式的文档
3. 系统自动进行OCR识别、文本提取和向量化
4. 观察处理进度和状态，确保所有文档处理完成
5. 创建新版本并提交发布
6. 通过审核后，创建AI Agent并关联该RAG数据集
7. Agent可以使用混合检索快速查找相关文档内容并回答问题

**关键特性：**
- 支持多种文档格式
- 自动化处理流程
- 版本管理和发布管控
- 高效的混合检索

### 场景2：法律文档智能检索

**需求描述：**
律师事务所需要快速从大量法律文书中检索相关条款和判例，为客户提供准确的法律建议。

**使用流程：**
1. 上传法律文书、判决书、法规文档
2. 使用混合检索（向量+关键词）确保全面检索
3. 设置高相似度阈值保证结果准确性
4. 启用重排序提升结果相关度
5. AI Agent基于检索结果生成法律建议
6. 展示检索到的原文内容，支持验证和引用

**关键特性：**
- 混合检索确保查全率和查准率
- RRF融合算法优化结果排序
- 重排序进一步提升准确性
- 展示原文出处，支持验证

### 场景3：产品文档智能问答

**需求描述：**
软件公司需要让客服系统自动回答用户关于产品功能、故障排除的问题，提升服务效率。

**使用流程：**
1. 创建产品文档数据集，上传产品手册、FAQ、故障排除指南
2. 配置Embedding模型和检索参数
3. 创建AI Agent，关联RAG数据集
4. 用户提问时，Agent自动检索相关文档
5. 基于检索结果生成自然语言回答

**关键特性：**
- 自动文档处理和向量化
- 智能检索和答案生成
- 支持实时更新文档内容
- 可重新向量化确保时效性

### 场景4：学术研究文献检索

**需求描述：**
研究机构需要快速从大量学术论文、报告中检索相关研究成果，辅助科研工作。

**使用流程：**
1. 上传PDF格式的学术论文、研究报告
2. OCR识别提取文本内容
3. 创建多个研究领域的数据集（如计算机、医学、工程）
4. 使用HyDE技术提升对复杂查询的理解
5. 检索结果按相似度排序，支持查看原文
6. 研究人员基于检索结果进行二次分析

**关键特性：**
- PDF OCR识别支持
- 多数据集分类管理
- HyDE技术提升复杂查询准确性
- 支持原文查看和引用

### 场景5：RAG能力市场共享

**需求描述：**
用户可以将自己构建的优质RAG数据集发布到市场，供其他用户使用和订阅。

**使用流程：**
1. 用户构建和优化自己的RAG数据集
2. 创建版本并提交发布申请
3. 填写版本说明和使用文档
4. 等待管理员审核
5. 审核通过后，版本在RAG市场展示
6. 其他用户可以浏览、安装该RAG版本
7. 安装后可创建Agent使用该数据集

**关键特性：**
- 版本发布和审核机制
- RAG市场展示和管理
- 支持其他用户安装和使用
- 促进优质能力共享

### 场景6：动态文档更新

**需求描述：**
企业文档经常更新，需要确保RAG数据集中的内容与最新文档同步。

**使用流程：**
1. 上传更新后的文档文件
2. 系统重新进行OCR和向量化
3. 查看处理状态确保完成
4. 创建新版本或更新现有版本
5. 发布更新后的版本
6. Agent自动使用新版本的检索结果

**关键特性：**
- 支持文档更新和重新处理
- 版本历史管理
- 手动编辑文档单元内容
- 重新向量化指定内容

| 向量检索 | 基于语义相似度的向量检索 |

| 重排序 | 对检索结果进行二次优化排序 |

### 高级特性
- **异步处理**：文件处理、向量化等耗时操作异步执行
- **状态机驱动**：文档处理状态机确保流程可控
- **策略模式**：支持多种文档处理策略，易于扩展
- **并行检索**：向量和关键词检索并行执行，提升效率

  - `DocumentProcessingStrategy`：文档处理策略接口
  - `VectorStore`：向量存储接口
  - `SearchAlgorithm`：检索算法接口
  - `RerankStrategy`：重排序策略接口

## 非功能需求

### 性能要求
- 文档上传响应时间 < 2 秒（不包括异步处理时间）
- 检索响应时间 < 500ms（1000 个文档单元以内，P95）
- 检索响应时间 < 1 秒（1 万个文档单元以内，P95）
- 支持单数据集至少 10 万个文档单元
- 向量化吞吐量 ≥ 100 文档单元/分钟（取决于 Embedding 模型）
- 支持并发检索请求 ≥ 100 QPS
- 混合检索延迟增加不超过 200ms
- 重排序延迟增加不超过 300ms
- 系统启动时间 < 30 秒

### 可用性要求
- 系统可用性 ≥ 99.9%
- 故障恢复时间 < 5分钟
- 数据持久化可靠性 ≥ 99.999%

### 安全性要求
- 数据集和文件严格按用户隔离，禁止跨用户访问
- 文件上传需进行类型验证、大小限制和恶意内容检测
- 支持 XSS 防护，对上传的文件名和内容进行过滤
- 向量数据在传输和存储过程中需加密
- 敏感内容过滤：发布到市场的 RAG 需经过敏感词检测和审核
- 支持文件病毒扫描（可选集成 ClamAV 等）
- 审计日志记录所有关键操作（创建、删除、发布等）
- API 访问需进行身份验证和权限校验
- 支持基于角色的访问控制（RBAC）

### 可扩展性要求
- 支持水平扩展向量存储节点
- 支持分布式文件存储（MinIO、S3 等）
- 支持新增文档处理策略（通过策略工厂模式）
- 支持新增检索算法（通过策略模式）
- 支持自定义分段策略
- 支持多种 Embedding 模型热插拔
- 支持多租户和配额管理
- 提供插件机制支持第三方扩展

## 约束条件

### 技术约束
- 基于 LangChain、LlamaIndex 或 Haystack 框架实现 RAG 功能
- 使用 OpenAI 兼容的 Embedding API 或本地 Embedding 模型（如 sentence-transformers）
- 向量存储支持 PGVector（使用 psycopg2 驱动）、Milvus、Chroma 等
- OCR 支持 Tesseract、EasyOCR 或云服务 OCR API
- 需要与 LLM 管理模块、文件存储模块集成
- 使用 pgvector 进行向量相似度计算时，需安装 PostgreSQL 扩展

### 业务约束
- 需要配置有效的 Embedding 模型
- 需要配置有效的 LLM 模型（用于重排序和对话）
- 发布到市场的 RAG 需要审核通过
- 用户配额限制（文件数量、文档单元数量等）
- 计费集成：RAG 操作（上传、向量化、检索）需记录用量并计费
- 配额与计费挂钩，超额需升级套餐或购买额外配额

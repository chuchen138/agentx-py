# LLM 管理能力模块 - 需求规格说明

## 概述

LLM（Large Language Model）管理模块是 AgentX 平台的核心能力之一，负责管理多服务商支持、协议适配、模型配置和高可用切换等功能。该模块提供统一的服务商和模型管理能力，支持用户自定义接入各类大模型服务，并通过高可用网关实现智能路由和故障转移，为 AI Agent 提供稳定可靠的大模型服务调用能力。

## 核心能力

### 1. 多服务商支持

#### 1.1 服务商类型
系统支持三种类型的服务商：
- **官方服务商**：由平台管理员预配置的官方服务商
- **用户自定义服务商**：用户自行接入的服务商
- **混合模式**：同时使用官方和用户服务商

#### 1.2 支持的协议
通过协议适配器模式，支持多种 LLM 服务协议：
- OpenAI 协议（包括兼容 OpenAI 格式的服务）
- Moonshot 协议
- Azure OpenAI 协议
- 其他兼容协议（可扩展）

#### 1.3 服务商配置
每个服务商包含以下核心配置：
- **基本信息**：名称、描述、协议类型
- **连接配置**：API Key、Base URL（自定义服务商Endpoint）
- **状态管理**：启用/禁用状态、官方标记
- **权限控制**：用户级（仅创建者可用）或系统级（所有用户可用）

### 2. 模型管理

#### 2.1 模型类型
支持两种模型类型：
- **对话模型（CHAT）**：用于对话、推理等生成式任务
- **嵌入模型（EMBEDDING）**：用于文本向量化、语义检索

#### 2.2 模型属性
每个模型包含以下核心属性：
- **基本信息**：模型ID、名称、描述
- **归属关系**：所属服务商ID
- **部署配置**：模型部署名称（modelEndpoint）
- **状态管理**：启用/禁用状态、官方标记
- **模型类型**：CHAT 或 EMBEDDING

#### 2.3 服务商-模型聚合
采用聚合根模式，将服务商和其下的模型作为整体管理：
- 服务商聚合根（ProviderAggregate）包含服务商实体和模型列表
- 支持高效的批量查询和状态联动
- 保证数据一致性

#### 2.4 模型操作
- **创建模型**：在指定服务商下创建新模型
- **更新模型**：修改模型配置和属性
- **删除模型**：删除指定模型（含级联处理）
- **状态切换**：启用/禁用模型
- **批量操作**：支持批量删除模型

### 3. 高可用网关

#### 3.1 智能路由
- **自动选择**：根据模型配置和健康状态自动选择最佳服务商和模型实例
- **会话亲和性**：同一会话优先使用相同的模型实例，保持上下文一致性
- **负载均衡**：在多个可用实例之间进行负载分配
- **故障转移**：当主实例不可用时自动切换到备用实例

#### 3.2 降级机制
- **降级链**：支持配置模型降级顺序，当主模型失败时依次尝试备用模型
- **自动降级**：根据调用历史和错误率自动触发降级
- **手动降级**：管理员可手动指定降级策略

#### 3.3 性能监控
- **调用结果上报**：记录每次调用的成功与否、延迟、错误信息
- **健康度评估**：基于历史调用数据评估模型实例健康度
- **动态调整**：根据监控数据动态调整路由策略

#### 3.4 高可用功能
- **模型同步**：将模型信息同步到高可用网关
- **状态变更**：实时同步模型启用/禁用状态
- **批量操作**：支持批量同步、批量删除模型实例
- **项目初始化**：一次性初始化项目所有模型到网关

### 4. 领域事件

#### 4.1 模型生命周期事件
- **ModelCreatedEvent**：模型创建时触发
- **ModelUpdatedEvent**：模型更新时触发
- **ModelDeletedEvent**：模型删除时触发
- **ModelStatusChangedEvent**：模型状态变更时触发
- **ModelsBatchDeletedEvent**：批量删除模型时触发

#### 4.2 事件驱动处理
通过领域事件机制实现解耦：
- 高可用模块监听模型变更事件，自动同步到网关
- 统计模块监听调用事件，记录使用数据
- 监控模块监听错误事件，触发告警

### 5. 配置管理

#### 5.1 配置加密
- **敏感信息保护**：API Key 等敏感配置通过加密存储
- **运行时解密**：聚合根提供解密后的配置访问
- **掩码显示**：前端返回 API Key 掩码（如 *****），保护密钥安全

#### 5.2 配置验证
- **协议验证**：创建/更新服务商时验证协议类型是否支持
- **必填校验**：确保必要配置项已填写
- **格式校验**：验证 URL、Key 等格式正确性

### 6. 权限与安全

#### 6.1 用户隔离
- **用户级资源**：用户创建的服务商和模型仅其自身可见
- **官方资源**：官方服务商和模型对所有用户可见
- **权限校验**：操作时校验用户是否具有资源访问权限

#### 6.2 操作权限
- **用户操作**：用户只能操作自己创建的服务商和模型
- **管理员操作**：管理员可以管理所有服务商和模型（包括官方资源）
- **级别标记**：通过 Operator 标识操作者级别（USER/ADMIN）

### 7. API 查询能力

#### 7.1 服务商查询
- **获取所有服务商**：包含官方和用户自定义服务商
- **获取官方服务商**：仅返回平台预配置的官方服务商
- **获取用户自定义服务商**：仅返回用户自己创建的服务商
- **按类型查询**：根据 ProviderType（ALL/OFFICIAL/CUSTOM）筛选

#### 7.2 模型查询
- **获取激活模型**：按服务商类型和模型类型筛选激活的模型

#### 7.3 协议查询
- **获取支持的协议列表**：返回系统支持的所有 ProviderProtocol

#### 7.4 用户偏好设置
- **保存用户模型偏好设置**：保存用户当前使用的模型
- **获取用户模型偏好设置**：获取用户之前保存的模型设置

#### 7.5 模型对话
- **与模型对话**：向指定模型发送消息并获取响应

### 8. MCP 集成支持

#### 8.1 MCP Server 注册
- **自动注册**：LLM 服务商可作为 MCP Server 注册到 MCP Hub
- **工具暴露**：将 LLM 调用能力封装为 MCP Tool
- **动态发现**：支持 MCP Client 动态发现可用的 LLM 服务

#### 8.2 协议转换
- **MCP 协议适配**：将 LLM 请求转换为 MCP Tool Call 格式
- **响应标准化**：将 LLM 响应转换为 MCP Tool Result 格式

## 技术约束

### 1. 技术栈要求

#### 1.1 核心框架
- **Web 框架**：FastAPI 0.104+
- **ORM 框架**：SQLAlchemy 2.0+
- **数据验证**：Pydantic 2.0+
- **异步支持**：AsyncIO（原生异步）

#### 1.2 协议适配
- **优先方案**：llama-index 或 haystack 作为协议适配层
- **备选方案**：自定义 httpx 客户端实现
- **禁止使用**：LangChain4j（Java 库，与项目技术栈冲突）

#### 1.3 基础设施
- **数据库**：PostgreSQL 14+
- **缓存**：Redis 7.0+
- **消息队列**：RabbitMQ 3.10+（用于事件驱动）
- **监控**：Prometheus + prometheus_client

### 2. 性能要求

#### 2.1 响应时间
- **模型选择延迟**：< 50ms（P95）
- **API 响应时间**：< 200ms（P95，不含 LLM 调用时间）
- **故障转移时间**：< 1s（检测到故障到切换备用模型）
- **缓存命中率**：> 80%（热点数据如官方模型列表）

#### 2.2 并发能力
- **并发连接数**：支持 1000+ 并发连接
- **QPS**：单实例支持 500+ QPS
- **水平扩展**：支持通过增加实例线性提升容量

#### 2.3 可用性
- **服务可用性**：> 99.9%
- **数据持久性**：> 99.99%
- **故障恢复时间**：< 5 分钟

### 3. 安全要求

#### 3.1 数据加密
- **API Key 加密**：AES-256-GCM 加密存储
- **传输加密**：强制 HTTPS/TLS 1.3
- **密钥管理**：使用环境变量或专用密钥管理服务

#### 3.2 访问控制
- **用户隔离**：严格的用户级资源隔离，防止越权访问
- **权限校验**：所有操作必须经过权限验证
- **审计日志**：记录所有敏感操作（创建、更新、删除）

#### 3.3 防护措施
- **密钥轮换**：支持定期轮换（建议周期 90 天）
- **配额限制**：官方模型设置调用配额，防止滥用
- **限流控制**：API 级别限流，防止 DDoS 攻击
- **输入验证**：严格验证所有输入参数

#### 3.4 风险控制
- **模型共享风险**：官方模型需设置访问日志和配额监控
- **异常检测**：检测异常调用模式（如高频调用、大额消耗）
- **告警机制**：异常情况实时告警

### 4. 可扩展性要求

#### 4.1 协议扩展
- **抽象基类**：定义 ProtocolAdapter 抽象基类
- **扩展钩子**：提供 register_adapter() 方法注册新协议
- **配置映射**：新增协议只需添加配置映射，无需修改核心代码

#### 4.2 高可用策略扩展
- **策略接口**：定义 RoutingStrategy 接口
- **动态加载**：支持运行时动态加载新策略
- **配置化**：通过配置文件选择策略

#### 4.3 模型类型扩展
- **枚举扩展**：ModelType 枚举支持新增类型
- **向后兼容**：新增类型不影响现有功能

### 5. 依赖关系

#### 5.1 依赖模块
- **用户管理模块**：获取用户信息和权限
- **高可用模块**：依赖其实现智能路由和故障转移
- **监控模块**：上报指标和日志
- **MCP Hub**：如需 MCP 集成

#### 5.2 被依赖模块
- **对话模块**：消费 LLM 管理能力
- **Agent 模块**：消费 LLM 管理能力
- **RAG 模块**：可能使用嵌入模型

## 使用场景

### 场景 1：用户使用官方模型
**流程描述**：
1. 用户查看官方服务商列表
2. 选择合适的官方服务商及其模型
3. 系统返回可用的官方模型供用户使用
4. 调用时高可用网关自动选择最优实例

### 场景 2：用户自定义接入第三方模型
**流程描述**：
1. 用户选择支持的协议类型（如 OpenAI 兼容协议）
2. 填写服务商信息（名称、API Key、Base URL）
3. 在该服务商下创建模型配置
4. 启用模型后即可在对话中使用
5. 高可用网关自动将该模型纳入管理

### 场景 3：高可用智能路由
**流程描述**：
1. 用户发起对话请求
2. 高可用网关根据模型配置、健康度、会话亲和性选择最佳实例
3. 调用模型服务
4. 记录调用结果（成功/失败、延迟）
5. 如果调用失败，自动尝试备用实例

### 场景 4：模型故障转移
**流程描述**：
1. 配置主模型和备用模型的降级链
2. 主模型调用失败时触发降级
3. 自动切换到备用模型继续服务
4. 同时上报失败结果到高可用网关
5. 网关根据历史数据调整该模型的健康度评分

### 场景 5：管理员管理官方资源
**流程描述**：
1. 管理员创建官方服务商
2. 配置服务商连接信息
3. 在官方服务商下创建预置模型
4. 设置为官方资源（对所有用户可见）
5. 监控官方资源的使用情况和性能指标

## 功能特性

### 1. 多协议统一管理
- 通过协议适配器模式统一不同 LLM 服务的接口
- 新增协议支持时无需修改核心代码
- 支持协议扩展和自定义实现

### 2. 弹性伸缩能力
- 用户可自由添加服务商和模型
- 支持动态启用/禁用服务
- 高可用网关自动适应资源变化

### 3. 智能容错
- 自动故障检测和转移
- 降级链配置灵活
- 调用结果实时监控

### 4. 数据安全
- API Key 加密存储
- 前端掩码显示
- 用户级别隔离

### 5. 开放扩展
- 支持新增服务商协议（通过 ProtocolAdapter 扩展）
- 支持自定义高可用策略（通过 RoutingStrategy 接口）
- 领域事件驱动解耦
- MCP 集成支持

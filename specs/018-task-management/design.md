# 任务管理技术设计

## 概述

任务管理能力采用分层架构设计，遵循领域驱动设计（DDD）原则，提供任务聚合和状态管理能力。

## 技术架构

### 架构分层

系统采用四层架构：接口层处理 HTTP 请求，定义 DTO，参数校验；应用层负责业务流程编排，DTO 转换，调用领域服务（TaskAppService）；领域层包含核心业务逻辑，实体模型，领域服务，聚合根（TaskEntity、TaskStatus、TaskAggregate、TaskDomainService）；基础设施层负责数据库访问，数据持久化（TaskRepository）。

### 核心组件

TaskAppService 负责任务管理相关的业务流程编排，包括获取当前会话的任务、聚合任务和子任务、提供任务查询能力。TaskDomainService 负责任务的领域逻辑处理，包括查询任务聚合、任务状态更新和任务进度更新。

## 核心设计

### 任务实体和枚举

任务实体包含任务 ID、所属会话 ID、用户 ID、父任务 ID、任务名称、任务描述、任务状态、任务进度、开始时间、结束时间和任务结果等字段。使用 UUID 生成唯一 ID，parentTaskId 建立任务层级关系，提供进度字段支持任务进度跟踪。TaskEntity 提供 updateStatus 方法，根据状态自动设置开始/结束时间。TaskStatus 枚举定义了 WAITING（等待中）、IN_PROGRESS（进行中）、COMPLETED（已完成）、FAILED（失败）等任务状态。

### 任务聚合根

任务和子任务形成树形结构，聚合根提供整体管理能力，支持检查整体完成状态。TaskAggregate 包含 TaskEntity 和子任务列表，提供检查所有任务是否完成的方法。任务和子任务形成一个聚合，通过聚合根管理整体生命周期，保证数据一致性。TasksAggregate 包含 TaskEntity 和子任务列表，父任务的状态由子任务状态决定，所有子任务完成后父任务才完成。

### 任务查询和状态管理

获取当前会话的聚合任务时，查询父任务（parent_task_id 为空）和子任务（parent_task_id 等于父任务 ID），构建聚合根返回结果。任务状态的转换有明确的业务规则，开始和结束时间自动设置，减少手动错误。TaskEntity 提供 updateStatus 方法，状态转换时自动设置时间，禁止非法状态转换。

### 数据持久化

系统设计了任务表结构，包含任务 ID、会话 ID、用户 ID、父任务 ID、任务名称、描述、状态、进度、时间等信息，并为常用查询字段建立索引。

## 关键设计决策

使用聚合根模式的优点是任务和子任务形成一个聚合，通过聚合根管理整体生命周期，保证数据一致性。任务状态的自动管理减少了手动错误，使用 updateStatus 方法自动设置时间。查询优化策略包括只查询必要的任务数据、使用 SQL 排序获取最新任务、避免 N+1 查询问题。

## 性能优化

为常用查询字段建立索引，使用覆盖索引，避免全表扫描。缓存最近访问的任务，使用短期缓存，实现缓存过期策略。支持批量更新任务状态，减少数据库操作次数，使用事务保证一致性。

## 扩展性设计

支持不同类型的任务，如工作流任务、子任务和工具调用任务。支持任务优先级，控制任务执行顺序。支持任务之间的依赖关系。支持失败任务的重试机制，记录重试次数和最大重试次数。

## 集成与安全

### 模块集成

任务与会话绑定，每个会话可以有多个任务，任务属于特定的会话。任务是 Agent 执行产生的，任务内容与 Agent 能力相关，Agent 的任务分解逻辑创建任务。定时任务可以创建会话任务，定时任务执行时设置任务结果，定时任务的状态与会话任务关联。任务的开始和结束时间与执行追踪对齐，任务的执行状态记录到执行追踪，支持通过执行追踪查看任务执行详情。子任务可以是工具调用任务，任务结果包含工具调用的返回信息，支持跟踪工具调用的成功或失败。

### 安全设计

用户只能访问自己的任务，任务访问需要权限验证，禁止跨用户任务访问。任务描述中可能包含敏感信息，任务结果中可能包含敏感数据，支持脱敏处理。记录任务创建、更新和删除操作，支持操作追溯。

### 数据一致性

任务更新使用事务，保证多个任务同时更新的一致性，支持事务回滚。使用乐观锁避免并发更新冲突，通过 version 字段实现。外键约束保证关联完整性，使用数据库约束保证数据有效性，定期检查数据一致性。

## 技术栈

Spring Boot、MyBatis-Plus、MySQL、Spring IoC、Spring Cache（支持 Redis、Caffeine）。

## 未来演进方向

引入消息队列实现异步任务执行，支持集群环境下的任务分发，支持任务的负载均衡。引入专用的任务编排框架，支持可视化任务流程，支持复杂的任务编排和依赖管理。提供任务执行的实时监控，统计任务执行成功率、平均耗时等，提供任务执行分析和优化建议。支持任务模板功能，用户可以基于模板快速创建任务，支持模板的参数化配置。

# Tool Integration 能力规范

## 概述

工具集成模块为 AgentX 平台提供第三方工具接入能力，支持用户上传管理自定义工具，通过 MCP（Model Context Protocol）协议实现工具的发现、部署、审核和发布，为 Agent 生态扩展丰富的外部能力。

## 核心能力

### 1. 工具接入流程

工具接入是指用户将其开发或维护的工具集成到 AgentX 平台的过程，支持通过 GitHub 仓库进行工具源码管理，平台自动化完成审核、部署和验证。

#### 1.1 接入方式
- **GitHub 仓库接入**：用户通过提供 GitHub 仓库 URL，平台自动拉取代码并完成验证
- **MCP 协议兼容**：工具需符合 MCP 协议规范，提供标准化的工具定义

#### 1.2 接入步骤
1. 用户提交工具信息（名称、描述、GitHub 仓库 URL 等）
2. 系统验证 GitHub 仓库的合法性和可访问性
3. 系统自动将工具部署到审核容器
4. 系统从容器中获取工具定义列表
5. 等待平台管理员人工审核
6. 审核通过后自动创建初始版本
7. 工具发布到工具市场，可供其他用户安装使用

### 2. GitHub 验证

为了保证工具来源的安全性和可靠性，系统对接入的 GitHub 仓库进行严格验证。

#### 2.1 验证内容
- **仓库存在性验证**：确认 GitHub 仓库存在且可访问
- **引用有效性验证**：验证指定的分支或标签引用是否存在
- **路径有效性验证**：确认工具源码路径在仓库中存在
- **MCP 规范验证**：验证工具配置是否符合 MCP 协议规范

#### 2.2 验证失败处理
验证失败时，系统会自动将工具状态置为 FAILED，并记录详细失败原因，用户可根据失败原因修正后重新提交。

### 3. 工具部署

工具部署是指将工具从 GitHub 仓库部署到平台的审核容器，以便进行工具定义获取和审核。

#### 3.1 部署流程
1. 解析工具安装命令（installCommand），提取 MCP 服务器配置
2. 从审核容器服务获取容器连接信息（IP、端口）
3. 调用 MCP Gateway 服务将工具部署到审核容器
4. 等待容器中工具启动完成

#### 3.2 部署异常处理
- 安装命令为空时拒绝部署
- MCP Gateway 部署失败时更新工具状态为 FAILED
- 记录详细错误信息供用户排查

### 4. 工具审核

工具审核包含自动化检查和人工审核两个阶段，确保工具的质量和安全性。

#### 4.1 自动化检查
- **GitHub 验证**：验证仓库合法性和可访问性
- **工具部署**：将工具部署到审核容器
- **工具定义获取**：从容器中提取工具定义列表，包含工具名称、描述、输入输出参数等信息
- **MCP 规范兼容性**：验证工具定义符合 MCP 协议规范

#### 4.2 人工审核
- **审核入口**：审核人员可进入 MANUAL_REVIEW 状态的待审核工具列表
- **审核内容**：查看工具定义、工具描述、功能说明等核心信息
- **审核结论**：
  - **通过**：工具状态变为 APPROVED，自动创建初始版本并上架工具市场
  - **拒绝**：工具状态变为 FAILED，记录拒绝原因，用户需修正后重新提交

#### 4.3 审核通过后处理
- 自动为工具创建者安装审核通过的工具（避免创建者无法使用自己创建的工具）
- 无已发布版本时创建内部基础版本（版本号 0.0.0）
- 工具发布到工具市场，供其他用户查看和安装

### 5. 工具发布

工具发布是指将审核通过的工具上架到工具市场，供其他用户查看、安装和使用。

#### 5.1 发布条件
- 工具状态必须为 APPROVED（已通过审核）
- 工具必须有明确的版本号
- 版本号必须严格大于上一版本号（语义化版本号比较）

#### 5.2 发布内容
- 工具基本信息（名称、描述、图标等）
- 工具版本信息（版本号、更新日志）
- 工具定义（工具列表、参数定义）
- MCP 服务器信息

#### 5.3 发布流程
1. 用户选择已审核通过的工具，填写版本号和更新日志
2. 系统验证版本号是否大于当前最新版本号
3. 创建 ToolVersionEntity 实体，保存工具版本信息
4. 设置版本公开状态为 true
5. 工具上架到工具市场

### 6. 工具安装与卸载

工具安装是指用户将市场上的工具安装到自己的工作空间，为自己的 Agent 提供使用该工具的能力。

#### 6.1 工具安装
- **安装方式**：用户从工具市场选择工具进行安装
- **安装内容**：
  - 工具基本信息
  - 工具版本信息
  - MCP 服务器名称
  - 安装命令
- **安装限制**：
  - 用户不允许卸载自己创建的工具（需要通过删除工具完成）
  - 已安装的工具重复安装时会更新到新版本
- **自动安装**：工具审核通过后，系统自动为工具创建者安装审核通过的工具

#### 6.2 工具卸载
- **卸载方式**：用户选择已安装的工具进行卸载
- **卸载结果**：删除用户的工具安装记录，不影响工具创建者和其他用户
- **卸载限制**：用户不允许卸载自己创建的工具，避免误删除

## 使用场景

### 场景 1：开发者自研工具接入平台

某开发者基于 MCP 协议开发了一个数据查询工具，希望将其接入 AgentX 平台供自己和他人使用。

**流程**：
1. 开发者在 GitHub 创建仓库并上传工具源码，配置 MCP 协议相关文件
2. 登录 AgentX 平台，进入工具管理页面，点击"上传工具"
3. 填写工具信息（名称、描述等）和 GitHub 仓库 URL
4. 系统自动验证 GitHub 仓库合法性和 MCP 规范兼容性
5. 系统将工具部署到审核容器，并获取工具定义
6. 等待平台管理员人工审核（管理员查看工具定义和功能说明）
7. 审核通过后，系统自动为开发者安装该工具（开发者可立即使用）
8. 开发者在工具市场填写版本号和更新日志，点击"发布"
9. 工具上架工具市场，其他用户可查看和安装

### 场景 2：用户从工具市场安装工具

某用户希望为 Agent 添加图像识别能力，在工具市场发现了适用的工具。

**流程**：
1. 用户登录 AgentX 平台，进入工具市场页面
2. 用户浏览工具市场，查看工具列表、工具详情、安装数量等信息
3. 用户选择"图像识别工具"，点击"安装"按钮
4. 系统创建用户工具安装记录，记录工具版本和 MCP 服务器信息
5. 用户的 Agent 可以使用该工具进行图像识别任务
6. 用户可在"已安装工具"页面查看和管理已安装的工具

### 场景 3：工具版本更新与升级

某工具开发者在原有功能基础上进行了优化和扩展，希望发布新版本供用户使用。

**流程**：
1. 开发者将更新的工具代码推送到 GitHub 仓库
2. 登录 AgentX 平台，进入工具管理页面，选择需要更新的工具
3. 点击"更新工具"，填写更新信息
4. 系统重新验证 GitHub 仓库和部署工具
5. 等待管理员审核新版本
6. 审核通过后，开发者发布新版本（版本号必须大于上一版本号，例如 1.0.1 → 1.1.0）
7. 用户可在工具市场查看版本历史，选择新版本进行升级

### 场景 4：工具审核拒接后重试

某开发者上传的工具因不符合 MCP 规范被审核拒绝。

**流程**：
1. 开发者收到工具审核失败通知，查看失败原因（例如"工具定义格式错误"）
2. 开发者修正 GitHub 仓库中的工具配置文件，确保符合 MCP 规范
3. 登录 AgentX 平台，重新提交工具或更新工具
4. 系统重新进行 GitHub 验证和工具部署
5. 等待管理员再次审核
6. 审核通过后，工具上架工具市场

## 功能特性

### 1. 状态机自动化流转

工具接入过程采用状态机模式，实现状态自动流转和错误处理。

**状态定义**：
- `WAITING_REVIEW`：等待审核（初始状态）
- `GITHUB_URL_VALIDATE`：GitHub URL 验证中
- `DEPLOYING`：工具部署中
- `FETCHING_TOOLS`：获取工具列表中
- `MANUAL_REVIEW`：人工审核中（需要人工介入）
- `APPROVED`：审核通过
- `FAILED`：审核失败

**流转规则**：
- WAITING_REVIEW → GITHUB_URL_VALIDATE（自动）
- GITHUB_URL_VALIDATE → DEPLOYING（验证成功自动，验证失败 → FAILED）
- DEPLOYING → FETCHING_TOOLS（部署成功自动，部署失败 → FAILED）
- FETCHING_TOOLS → MANUAL_REVIEW（自动）
- MANUAL_REVIEW → APPROVED（人工审核通过）或 FAILED（人工审核拒绝）

### 2. 异步处理能力

### 2. 异步处理能力

长期运行的操作（如部署、获取工具列表）采用异步处理机制，避免阻塞用户请求。

**实现机制**：
- 使用线程池异步执行状态处理器
- 状态处理器执行完成后自动触发下一状态
- 失败时自动更新状态为 FAILED 并记录错误信息

### 3. 审核容器隔离

工具部署到专用的审核容器，与生产环境隔离，确保审核过程安全稳定。

**容器特性**：
- 独立的 IP 和端口
- 仅用于工具部署和审核
- 审核通过后工具可迁移至生产环境（或部署至新的容器）

### 4. 工具版本管理

工具支持多版本管理，用户可追踪版本历史，选择合适版本使用。

**版本信息**：
- 版本号（语义化版本号，例如 1.0.0）
- 更新日志（版本变更说明）
- 创建时间
- 公开状态（true 表示已发布到市场）

### 5. 工具市场

工具市场为用户提供工具浏览、搜索、安装的一站式体验。

**市场功能**：
- 工具列表：分页展示已发布的工具
- 工具详情：查看工具信息、版本历史、安装数量等
- 工具搜索：按名称或描述搜索工具
- 工具安装/卸载：一键安装或卸载工具
- 工具推荐：随机展示 10 个推荐工具

### 6. 用户工具管理

用户可管理自己创建和已安装的工具。

**管理功能**：
- 我的工具列表：查看自己创建的工具
- 已安装工具列表：查看已安装的工具及其版本
- 工具删除：删除自己创建的工具
- 工具卸载：卸载已安装的工具
- 工具更新：更新工具信息并重新审核

## 接口约束

### 1. 工具信息校验
- 工具名称不能为空
- GitHub 仓库 URL 必须为有效的 GitHub 仓库链接
- 工具描述不能为空
- MCP 服务器配置必须符合 MCP 协议规范

### 2. 版本号规范
- 版本号必须符合语义化版本号规范（例如 1.0.0、1.1.2、2.0.0-beta）
- 新版本号必须严格大于当前最新版本号

### 3. 权限控制
- 用户只能查看自己创建和已安装的工具
- 用户只能卸载已安装的工具，不能卸载自己创建的工具
- 管理员拥有工具审核权限

### 4. 审核约束
- 只有 APPROVED 状态的工具才能发布到工具市场
- 只有 APPROVED 状态的工具才能安装
- 工具审核通过后，系统自动为工具创建者安装审核通过的工具

## 非功能性需求

### 1. 性能
- 状态转换响应时间小于 100ms
- 工具列表分页查询响应时间小于 500ms
- 工具详情查询响应时间小于 300ms

### 2. 可靠性
- 状态处理失败时自动更新为 FAILED 并记录错误信息
- 长时间运行的操作采用异步处理，避免阻塞用户请求
- 审核容器异常时工具状态更新为 FAILED

### 3. 可扩展性
- 支持新增状态处理器而无需修改现有代码
- 支持新增工具发布渠道（例如从私有 Git 仓库接入）
- 支持扩展 MCP 协议版本

### 4. 安全性
- GitHub 仓库 URL 验证确保来源合法
- 审核容器隔离确保审核过程安全
- 工具定义获取仅从审核容器获取，避免恶意代码执行

## 相关模块

- **容器管理（Container Management）**：提供审核容器的创建、监控、销毁能力
- **MCP Gateway**：提供工具部署、工具定义获取、工具执行等能力
- **GitHub 集成**：提供 GitHub 验证、仓库信息获取等能力
- **Agent 工作空间**：提供工具安装后的使用能力

## 技术术语

| 术语 | 说明 |
|-----|------|
| MCP（Model Context Protocol） | 模型上下文协议，用于标准化工具定义和交互 |
| 审核容器 | 用于工具审核的独立容器，与生产环境隔离 |
| 工具定义 | 描述工具的元数据，包括名称、描述、输入输出参数等 |
| 安装命令（installCommand） | 用于部署工具的命令，包含 MCP 服务器配置 |
| 状态机 | 用于管理工具状态的自动化流转机制 |
| 工具版本 | 工具的版本化标识，包含版本号、更新日志等信息 |
| 工具市场 | 展示已发布工具的平台模块，供用户浏览和安装 |

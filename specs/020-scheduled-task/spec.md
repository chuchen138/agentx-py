# 定时任务能力 - 需求说明与场景描述

## 1. 概述

定时任务能力是 AgentX 平台的自动化执行能力，提供用户创建定时任务、配置执行策略、管理任务状态的全流程支持。用户可以通过定时任务功能，让 Agent 按照指定的规则定期执行特定任务，实现自动化操作。

### 1.1 模块定位

- **核心作用**：为用户提供创建和管理定时任务的能力
- **服务对象**：平台用户（创建和管理定时任务）
- **应用场景**：定期报告生成、数据同步、定期通知、定时查询等

### 1.2 核心价值

- **灵活调度**：支持多种重复类型（立即执行、每日、每周、自定义间隔等）
- **任务管理**：提供完整的任务 CRUD 操作
- **状态控制**：支持任务的启用、暂停、恢复
- **执行监控**：记录任务的执行历史和状态
- **会话关联**：任务与 Agent 和会话绑定，记录执行上下文

---

## 2. 核心能力

### 2.1 定时任务创建

定时任务创建是核心功能，允许用户定义要执行的任务和执行策略。

#### 功能描述

- **任务创建**：用户创建新的定时任务
- **任务内容配置**：指定 Agent 要执行的内容
- **重复类型选择**：选择任务的重复类型
- **重复配置**：根据重复类型配置执行参数
- **会话关联**：将任务关联到特定会话
- **下次执行时间计算**：根据规则计算下次执行时间

#### 关键数据

**ScheduledTaskDTO（定时任务数据传输对象）**

- `id`：任务 ID
- `userId`：用户 ID
- `agentId`：Agent ID
- `sessionId`：会话 ID
- `content`：任务内容
- `repeatType`：重复类型
- `repeatConfig`：重复配置
- `status`：任务状态
- `lastExecuteTime`：上次执行时间
- `nextExecuteTime`：下次执行时间
- `createdAt`：创建时间
- `updatedAt`：更新时间

---

### 2.2 重复类型与配置

支持多种重复类型，满足不同的定时需求。

#### 重复类型（RepeatType）

**IMMEDIATE（立即执行）**

- 执行一次后结束
- 不需要重复配置

**INTERVAL（间隔重复）**

- 按固定时间间隔重复
- 配置：间隔小时数

**DAILY（每日重复）**

- 每天固定时间执行
- 配置：执行时间（HH:mm 格式）

**WEEKLY（每周重复）**

- 每周固定日期和时间执行
- 配置：星期几（1-7）、执行时间（HH:mm 格式）

**CUSTOM（自定义）**

- 自定义 Cron 表达式
- 配置：Cron 表达式字符串

#### 重复配置（RepeatConfig）

- `intervalHours`：间隔小时数（INTERVAL 类型使用）
- `executeTime`：执行时间（DAILY、WEEKLY 类型使用）
- `weekDays`：星期几列表（WEEKLY 类型使用）
- `cronExpression`：Cron 表达式（CUSTOM 类型使用）

---

### 2.3 任务调度

任务调度是定时任务能力的核心，负责在指定时间触发任务执行。

#### 功能描述

- **任务注册**：将任务注册到调度系统
- **时间计算**：根据配置计算下次执行时间
- **任务触发**：在指定时间触发任务执行
- **下次执行更新**：执行完成后更新下次执行时间
- **任务重新调度**：任务更新时重新计算并调度

#### 调度流程

```
任务创建/更新
   ↓
计算下次执行时间
   ↓
注册任务到调度器
   ↓
等待执行时间
   ↓
触发任务执行
   ↓
更新执行状态和时间
   ↓
计算下一次执行时间
   ↓
重新调度任务
```

---

### 2.4 任务管理

提供完整的管理功能，支持对任务的全生命周期管理。

#### 功能描述

- **任务查询**：查询用户的任务列表
- **任务详情查询**：获取单个任务的详细信息
- **任务更新**：更新任务内容和配置
- **任务删除**：删除不需要的任务
- **按会话查询**：查询特定会话的任务

---

### 2.5 状态管理

支持任务状态的变更和管理。

#### 任务状态（ScheduleTaskStatus）

**PENDING（待执行）**

- 任务已创建，等待执行

**RUNNING（执行中）**

- 任务正在执行

**COMPLETED（已完成）**

- 任务执行完成

**FAILED（执行失败）**

- 任务执行失败

**PAUSED（已暂停）**

- 任务已暂停，不会执行

#### 状态转换

```
PENDING → RUNNING → COMPLETED
   ↓
   FAILED

PENDING → PAUSED

PAUSED → PENDING
```

## 3. 核心场景

### 3.1 创建每日报告任务

用户创建一个每天早上 9 点执行的报告任务。

**场景描述**：

1. 用户进入定时任务管理页面
2. 点击"新建任务"
3. 填写任务内容："生成昨日销售报告"
4. 选择重复类型：每日
5. 配置执行时间：09:00
6. 选择关联的 Agent 和会话
7. 保存任务
8. 系统计算下次执行时间为明天 09:00
9. 将任务注册到调度器

**关键业务规则**：

- 任务创建后自动计算下次执行时间
- 每日重复在每天指定时间执行
- 支持选择具体的 Agent 和会话

### 3.2 创建间隔重复任务

用户创建一个每 2 小时执行一次的数据同步任务。

**场景描述**：

1. 用户创建新任务
2. 填写任务内容："同步客户数据"
3. 选择重复类型：间隔
4. 配置间隔：2 小时
5. 保存任务
6. 系统计算下次执行时间为 2 小时后
7. 任务每 2 小时执行一次

**关键业务规则**：

- 间隔配置的单位为小时
- 执行完成后重新计算下次执行时间

### 3.3 暂停和恢复任务

用户临时暂停某个任务，稍后恢复。

**场景描述**：

1. 用户查看任务列表
2. 找到需要暂停的任务
3. 点击"暂停"按钮
4. 任务状态变为 PAUSED
5. 调度器移除该任务的调度
6. 用户需要时点击"恢复"
7. 任务状态恢复到 PENDING
8. 重新计算并注册调度

**关键业务规则**：

- 暂停的任务不会被调度执行
- 恢复的任务重新计算执行时间

### 3.4 更新任务配置

用户修改任务的重复配置。

**场景描述**：

1. 用户进入任务详情页
2. 点击"编辑"
3. 修改重复类型或配置
4. 保存修改
5. 系统重新计算下次执行时间
6. 取消原调度，注册新调度

**关键业务规则**：

- 更新配置后重新调度
- 保持任务的状态和执行历史不变

### 3.5 查询执行历史

用户查看任务的执行历史。

**场景描述**：

1. 用户进入任务详情页
2. 查看"执行历史"标签
3. 系统展示任务的执行记录：
   - 执行时间
   - 执行状态
   - 执行结果
   - 错误信息（如果有）

**关键业务规则**：

- 记录每次任务执行的详细信息
- 执行历史保留一段时间

## 4. 数据模型

### 4.1 ScheduledTaskEntity

定时任务实体类，定义任务的基本结构。

| 字段名 | 类型 | 说明 |
|-------|------|------|
| id | String | 任务 ID |
| userId | String | 用户 ID |
| agentId | String | Agent ID |
| sessionId | String | 会话 ID |
| content | String | 任务内容 |
| repeatType | RepeatType | 重复类型 |
| repeatConfig | RepeatConfig | 重复配置 |
| status | ScheduleTaskStatus | 任务状态 |
| lastExecuteTime | LocalDateTime | 上次执行时间 |
| nextExecuteTime | LocalDateTime | 下次执行时间 |
| createdAt | LocalDateTime | 创建时间 |
| updatedAt | LocalDateTime | 更新时间 |

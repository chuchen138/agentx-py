# 账户计费能力 - 需求说明与场景描述

## 1. 概述

账户计费能力是 AgentX 平台的核心基础能力，提供账户余额管理、充值消费、订单管理、支付流程等功能模块。该能力为平台的各项服务（如模型调用、Agent使用、API调用、存储服务等）提供统一、灵活的计费基础，支撑平台商业化运营。

### 1.1 模块定位

- **核心作用**：为平台所有业务提供统一的计费基础服务
- **服务对象**：平台用户（充值、消费）、管理员（订单管理、商品配置）
- **业务类型**：模型调用、Agent创建/使用、API调用、存储使用等

### 1.3 技术约束

**技术栈要求**
- 后端框架：FastAPI + Python 3.10+
- 数据库：PostgreSQL 14+（事务隔离级别：READ COMMITTED）
- 缓存层：Redis 7.0+（余额缓存、分布式锁）
- 消息队列：Celery + Redis/RabbitMQ（异步扣费、对账任务）
- ORM：SQLAlchemy 2.0+（异步模式）

**性能指标**
- 余额检查延迟：< 50ms（P99）
- 扣费操作延迟：< 100ms（P99）
- 支付回调处理：< 200ms（P99）
- 系统并发能力：支持 1000+ QPS 扣费请求
- 高可用要求：99.9% 可用性，支持故障自动转移

**安全与合规要求**
- 支付数据加密：符合 PCI DSS Level 1 标准
- 敏感信息存储：支付凭证、订单号使用 AES-256 加密
- 防重放攻击：所有支付回调携带时间戳 + nonce，有效期 5 分钟
- 幂等性保障：基于唯一 request_id + 数据库唯一索引
- 防超扣保护：Redis 分布式锁 + 乐观锁（version 字段）
- 审计日志：所有余额变动记录完整审计轨迹，保留 3 年
- 大额操作验证：单笔充值 > 1000 元需二次确认（短信/邮箱）

**数据一致性**
- 充值流程：最终一致性（通过事件驱动 + 重试机制）
- 扣费流程：强一致性（数据库事务 + 行级锁）
- 对账机制：T+1 定时对账任务，差异自动告警

---

### 1.4 核心价值

- **灵活计费**：支持多种计费策略（按Token、按次、按时长、存储费等）
- **多支付渠道**：集成主流支付平台（支付宝、微信支付、Stripe）
- **事件驱动**：采用异步事件机制提升系统解耦和可扩展性
- **幂等保障**：基于请求ID防止重复计费
- **可配置化**：商品和规则配置化，支持动态调整价格策略

## 2. 核心能力

### 2.1 账户余额管理

账户余额管理是账户计费能力的基础，为每个用户维护账户信息。

#### 功能描述
- **用户账户创建**：用户注册时自动创建账户
- **账户余额查询**：用户可查看当前余额、信用额度、总消费金额
- **可用余额计算**：可用余额 = 账户余额 + 信用额度
- **余额充足性检查**：消费前检查账户余额是否充足
- **信用额度管理**：管理员可增加用户信用额度

#### 关键数据
- **账户余额（balance）**：用户实际拥有的资金
- **信用额度（credit）**：授予用户的临时额度
- **总消费金额（total_consumed）**：累计消费的总金额
- **最后交易时间（last_transaction_at）**：最近一次交易的时间

---

### 2.2 充值功能

充值功能允许用户通过第三方支付平台为账户充值。

#### 功能描述
- **创建充值订单**：用户发起充值请求，系统创建充值订单
- **多支付平台支持**：支持支付宝、微信支付、Stripe等支付平台
- **多支付方式支持**：支持网页支付、二维码支付、移动端支付、H5支付、小程序支付
- **支付成功自动到账**：支付成功后自动增加账户余额
- **支付状态查询**：用户可查询支付状态

#### 支付平台
- **支付宝（ALIPAY）**：扫码支付、网页支付、移动端支付
- **微信支付（WECHAT）**：扫码支付、小程序支付、H5支付
- **Stripe（STRIPE）**：国际支付支持

#### 支付类型
- **网页支付（WEB）**：PC端网页跳转支付
- **二维码支付（QR_CODE）**：扫码支付
- **移动端支付（MOBILE）**：移动端APP调起支付
- **H5支付（H5）**：H5页面内支付
- **小程序支付（MINI_PROGRAM）**：小程序内支付

---

### 2.3 消费计费

消费计费是根据用户资源使用情况自动扣费的核心功能。

#### 功能描述
- **自动扣费**：用户使用平台服务后自动从账户扣费
- **计费策略支持**：支持不同的计费策略（按Token、按次、按时长、存储费等）
- **费用计算**：根据用量数据和价格配置计算费用
- **最低计费保障**：小额计费自动归整为0.01元
- **消费记录**：记录每次计费的详细信息
- **余额检查**：扣费前检查余额是否充足

#### 计费类型

**模型调用计费（MODEL_USAGE）**
- 按输入输出Token数量计费
- 支持不同模型差异化定价
- 价格配置示例：
  ```json
  {
    "input_cost_per_million": 0.5,
    "output_cost_per_million": 1.5
  }
  ```

**Agent创建计费（AGENT_CREATION）**
- 按创建次数计费
- 每次创建Agent固定收费
- 价格配置示例：
  ```json
  {
    "cost_per_unit": 10.0
  }
  ```

**订阅计费（SUBSCRIPTION）**
- 包月/包年周期性自动续费
- 续费失败处理：
  - 宽限期：到期后 3 天宽限期，期间服务降级但不停止
  - 降级策略：余额不足时自动降级到基础模型
  - 重试机制：每 24 小时重试扣费，最多 3 次
  - 服务暂停：3 次失败后暂停服务，用户手动续费后恢复
- 退款规则：
  - 未使用可全额退款
  - 已使用按比例退款（剩余天数 / 总天数 × 实付金额）
  - 退款申请 48 小时内审核完成

**税费计算**
- 支持多税率配置（中国大陆 6%，美国各州不同税率）
- 价税分离显示：订单金额 = 不含税金额 + 税额
- 发票管理：支持电子发票开具（对接百望/航信）

**Agent 使用计费（AGENT_USAGE）**
- 按使用次数或资源消耗计费
- 根据 Agent 运行时资源使用量计费

**API调用计费（API_CALL）**
- 按API调用次数计费
- 支持套餐和分层计费

**存储使用计费（STORAGE_USAGE）**
- 按存储容量和时长计费
- 文件存储、向量存储费用

### 2.4 订单管理

订单管理提供完整的订单生命周期管理能力。

#### 功能描述
- **订单创建**：根据业务需求创建各类订单
- **订单状态流转**：支持订单状态流转（待支付、已支付、已取消、已退款、已过期）
- **订单查询**：用户查询自己的订单，管理员查询所有订单
- **订单筛选**：支持按订单类型、状态、时间等条件筛选

#### 订单类型

**充值订单（RECHARGE）**
- 用户账户充值
- 支付成功后触发余额增加

**购买订单（PURCHASE）**
- 购买商品或服务
- 使用余额或支付平台完成支付

**订阅订单（SUBSCRIPTION）**
- 订阅服务包月、包年
- 周期性自动续费

**续费订单（RENEWAL）**
- 服务续费
- 订阅到期后自动创建续费订单

#### 订单状态

**待支付（PENDING）**
- 订单已创建，等待用户支付

**已支付（PAID）**
- 用户已完成支付，订单生效

**已取消（CANCELLED）**
- 用户主动取消订单

**已退款（REFUNDED）**
- 订单已退款

**已过期（EXPIRED）**
- 订单超时未支付自动过期

---

### 2.5 支付流程

支付流程实现与第三方支付平台的集成，完成支付发起和回调处理。

#### 功能描述
- **支付发起**：调用第三方支付平台API创建支付
- **支付回调**：接收支付平台回调通知
- **状态同步**：同步支付状态到系统
- **事件触发**：支付成功后触发相关业务处理

#### 支付流程步骤
1. 用户发起充值请求
2. 系统创建充值订单（OrderType.RECHARGE）
3. 用户选择支付平台和支付类型
4. 系统调用支付平台API创建支付
5. 返回支付链接或二维码
6. 用户扫码或跳转完成支付
7. 支付平台回调通知支付结果
8. 系统更新订单状态为"已支付"
9. 发布 PurchaseSuccessEvent 事件
10. 事件监听器处理余额充值

## 3. 使用场景

### 3.1 账户充值场景

**场景描述**：用户需要为账户充值，以便使用平台的各项服务。

**用户操作流程**：
1. 用户登录平台，进入账户充值页面
2. 选择充值金额
3. 选择支付平台（支付宝、微信支付等）
4. 选择支付方式（扫码支付、网页支付等）
5. 提交充值请求
6. 系统创建充值订单
7. 跳转至支付页面或展示支付二维码
8. 用户扫码或在页面完成支付
9. 支付成功后系统自动增加账户余额
10. 用户可在账户页面查看充值成功信息和余额

**技术流程**：
1. PaymentAppService.createRechargePayment() 创建充值订单和支付
2. 支付平台回调通知
3. OrderDomainService 更新订单状态
4. 发布 PurchaseSuccessEvent 事件
5. RechargeEventListener 监听并处理充值事件
6. AccountAppService.recharge() 增加账户余额

---

### 3.2 模型调用计费场景

**场景描述**：用户调用 LLM 模型进行对话或文本生成，系统根据输入输出Token数量自动计费。

**业务流程**：
1. 用户发起对话请求
2. 系统调用 LLM 模型处理请求
3. 模型返回结果
4. 系统接收输入 Token 和输出 Token 数量
5. 计算费用：
   - 输入费用 = 输入Token数 / 1,000,000 × input_cost_per_million
   - 输出费用 = 输出Token数 / 1,000,000 × output_cost_per_million
   - 总费用 = 输入费用 + 输出费用
6. 检查账户余额是否充足
7. 扣除费用
8. 记录消费记录（包含Token数、费用、时间等信息）

**计费示例**：
- 输入 Token：1,000
- 输出 Token：500
- 价格配置：
  - input_cost_per_million: 0.5元
  - output_cost_per_million: 1.5元
- 计算：
  - 输入费用 = 1,000 / 1,000,000 × 0.5 = 0.0005 元
  - 输出费用 = 500 / 1,000,000 × 1.5 = 0.00075 元
  - 总费用 = 0.0005 + 0.00075 = 0.00125 元 ≈ 0.01 元（最低计费保障）

## 4. 消费上下文规范

### 4.1 统一消费上下文对象

所有消费场景必须传递统一的计费上下文，包含以下字段：

```json
{
  "user_id": "uuid",
  "agent_id": "uuid (可选)",
  "request_id": "uuid (幂等性控制)",
  "trace_id": "uuid (链路追踪)",
  "billing_type": "MODEL_USAGE | AGENT_CREATION | AGENT_USAGE | API_CALL | STORAGE_USAGE",
  "service_id": "model_id | agent_id | api_endpoint",
  "usage_data": {
    "input_tokens": 1000,
    "output_tokens": 500,
    "duration_seconds": 120,
    "storage_bytes": 1048576,
    "call_count": 1
  },
  "metadata": {
    "ip_address": "192.168.1.1",
    "user_agent": "Mozilla/5.0...",
    "timestamp": "2026-03-14T10:00:00Z"
  }
}
```

### 4.2 各模块集成方式

**与 004-llm-management 集成**
- LLM 调用成功后，从响应中提取 token_usage
- 构建 MODEL_USAGE 类型计费上下文
- 同步调用计费服务（< 100ms 延迟要求）

**与 005-apikey-management 集成**
- API Key 鉴权通过后，记录调用次数
- 按日/月统计 API 调用量
- 批量计费（每日凌晨结算前一日费用）

**与 002-file-storage 集成**
- 文件上传/删除时触发存储容量重算
- 每日定时任务计算存储费用（按量计费）
- 存储费用 = Σ(文件大小 × 存储天数 × 单价)

**与 010-agent-management 集成**
- Agent 创建成功时触发 AGENT_CREATION 计费
- Agent 执行完成时触发 AGENT_USAGE 计费
- 从执行追踪（016）获取资源消耗数据

### 4.3 退费与对账

**退款流程**
1. 用户提交退款申请（订单 ID + 原因）
2. 系统自动校验退款条件（订单状态、消费记录）
3. 管理员审核（> 500 元需人工审核）
4. 原路退回或退至账户余额
5. 更新订单状态为 REFUNDED
6. 记录退款审计日志

**定时对账任务**
- 频率：每日凌晨 2:00 执行 T+1 对账
- 对账范围：
  - 支付平台订单 vs 系统订单
  - 消费记录 vs 账户余额变动
  - 退款记录 vs 银行流水
- 差异处理：
  - 自动生成差异报告
  - 小额差异（< 0.1 元）自动平账
  - 大额差异触发告警 + 人工介入

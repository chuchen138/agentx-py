# 容器管理能力规范

## 概述

容器管理能力是 AgentX 平台的核心基础设施，提供基于 Docker 的容器化运行环境，支持用户隔离的 MCP 网关容器和工具审核容器。该能力动态管理容器的创建、监控、清理和智能恢复，确保平台工具部署和对话功能的稳定运行。

## 业务背景

### 需求来源

AgentX 平台需要为每个用户提供独立的容器化运行环境，以支持：
- **动态工具部署**：用户可以为 Agent 部署自定义工具，这些工具需要在隔离的环境中运行
- **工具审核**：管理员需要独立的审核容器来验证用户提交的工具
- **资源隔离**：通过容器隔离不同用户的工具执行环境，保障系统安全
- **资源优化**：智能化管理容器资源，自动清理闲置容器，降低系统成本

### 核心价值

1. **用户隔离**：每个用户拥有独立的容器环境，互不干扰
2. **资源弹性**：按需创建和销毁容器，最大化资源利用效率
3. **智能运维**：自动监控容器健康状态，异常时自动恢复
4. **审核安全**：独立的审核容器确保工具审核过程的安全可控

## 核心能力

### 1. 容器创建与生命周期管理

#### 1.1 用户容器创建

**能力描述**：为每个用户自动创建专属的 MCP 网关容器

**核心特性**：
- 按需创建：首次请求时自动创建用户容器
- 独立隔离：每个用户拥有独立的容器实例和端口
- 容器模板：基于预定义的容器模板快速创建
- 数据卷持久化：用户数据保存在独立的数据卷中

**使用场景说明**：

用户首次使用 Agent 对话功能时的处理流程：
- 系统自动检查用户容器是否存在
- 若不存在，基于 MCP 网关模板创建新容器
- 分配独立端口（30000-40000 范围）
- 挂载用户专属数据卷
- 返回容器连接信息

#### 1.2 审核容器创建

**能力描述**：为工具审核流程创建专用的审核容器环境

**核心特性**：
- 全局共享：整个系统使用一个审核容器
- 动态管理：不可用时自动重新创建
- 安全隔离：审核容器与用户环境完全隔离
- 快速恢复：审核容器异常时自动恢复

**使用场景说明**：

管理员审核用户提交工具时的处理流程：
- 获取审核容器连接信息
- 若容器不存在或不可用，自动创建
- 在审核容器中部署待审核工具
- 运行工具测试验证
- 审核完成后容器继续保持运行状态

#### 1.3 容器生命周期管理

**能力描述**：管理容器从创建到销毁的完整生命周期

**状态流转说明**：

容器生命周期状态转换流程：

**CREATING（创建中）**
- 成功 → RUNNING（运行中）
- 失败 → ERROR（错误状态）→ DELETED（已删除）

**RUNNING（运行中）**
- 用户停止 → STOPPED（已停止）
  - 手动启动 → RUNNING
  - 长期未使用 → DELETED
- 空闲超时 → SUSPENDED（已暂停）
  - 用户唤醒 → RUNNING
- 异常 → ERROR（错误状态）
  - 智能恢复 → RUNNING
- 主动删除 → DELETING（删除中）→ DELETED

**STOPPED（已停止）**
- 手动启动 → RUNNING
- 删除操作 → DELETING → DELETED

**SUSPENDED（已暂停）**
- 用户访问 → RUNNING
- 删除操作 → DELETING → DELETED

### 2. 容器监控与健康检查

#### 2.1 实时状态监控

**能力描述**：定时监控所有容器的运行状态和资源使用情况

**监控指标**：
- **容器状态**：创建中、运行中、已停止、错误、删除中、已删除、已暂停
- **Docker 状态**：实际容器存在性、运行状态
- **网络状态**：容器 IP 地址、外部端口、网络连通性
- **资源使用**：CPU 使用率、内存使用率

**监控策略**：
- **状态检查**：每 5 分钟执行一次全面状态检查
- **资源监控**：每 2 分钟更新一次 CPU/内存使用率
- **健康检查**：每次请求时进行快速健康验证

#### 2.2 智能健康检查

**能力描述**：多维度的容器健康检查机制

**检查维度**：

1. **数据库状态检查**
   - 验证容器记录的状态是否为 RUNING
   - 检查必要字段（IP 地址、端口、Docker 容器 ID）是否完整

2. **Docker 容器检查**
   - 验证 Docker 容器是否真实存在
   - 检查容器的实际运行状态
   - 确认容器网络的可用性

3. **网络连通性检查**
   - 测试容器 IP 和端口的可达性
   - 验证端口映射配置正确

**应用场景说明**：

用户请求使用容器时的健康检查流程：
- 调用 getUserContainer() 获取容器
- 执行健康检查：
  - 检查数据库状态
  - 检查 Docker 实际状态
  - 检查网络连通性
- 若不健康，触发智能恢复
- 返回可用的容器实例

### 3. 容器智能恢复

**能力描述**：自动检测和恢复异常容器，提升系统稳定性

**恢复策略说明**：

**Docker 容器重启**
- 适用场景：Docker 容器存在但未运行
- 处理方式：强制启动容器
- 后续操作：更新数据库状态为 RUNNING

**容器信息修正**
- 适用场景：容器正在运行但数据库状态不正确
- 处理方式：重新获取容器网络信息（IP、端口）
- 后续操作：更新数据库中的容器信息并同步状态

**完全重建容器**
- 适用场景：容器已不存在或无法恢复
- 处理方式：标记旧容器为 DELETED 状态，基于模板创建新容器
- 后续操作：重新分配端口和数据卷，启动新容器并更新状态

**恢复优先级**：
1. 优先尝试启动已存在的 Docker 容器
2. 其次尝试修正容器网络信息
3. 最后考虑完全重建容器

### 4. 容器自动清理

**能力描述**：基于使用策略自动清理闲置容器，优化资源利用率

#### 4.1 清理策略

**暂停策略**：
- **触发条件**：容器处于运行状态，且最后访问时间超过 24 小时
- **执行动作**：停止 Docker 容器，更新状态为 SUSPENDED
- **恢复机制**：下次用户访问时自动唤醒容器并恢复运行

**删除策略**：
- **触发条件**：容器状态为暂停或停止，且最后访问时间超过 5 天
- **执行动作**：删除 Docker 容器，更新状态为 DELETED
- **数据保留**：用户数据卷保留，可手动清理

#### 4.2 执行机制

**定时任务**：
- **执行频率**：每小时执行一次
- **执行时间**：系统低峰期（建议）

**清理流程说明**：

容器清理任务执行步骤：
- 查询需要暂停的容器（运行中，24 小时未访问）
  - 逐个停止 Docker 容器
  - 更新状态为 SUSPENDED
- 查询需要删除的容器（5 天未访问）
  - 逐个删除 Docker 容器
  - 更新状态为 DELETED
- 记录清理日志

### 5. 容器类型策略

#### 5.1 用户容器（USER）

**特性**：
- **数量**：每个用户一个容器
- **生命周期**：与用户账号绑定长期保留
- **功能**：支撑用户的 Agent 对话和工具部署
- **资源隔离**：独立的端口、数据卷、网络环境

**使用流程说明**：

用户容器的完整使用流程：
1. 用户登录
2. 首次使用 Agent 功能
3. 自动创建用户容器
4. 部署用户工具
5. 执行 Agent 对话
6. 容器长期保留（自动清理策略除外）


#### 5.2 审核容器（REVIEW）

**特性**：
- **数量**：全系统一个容器
- **生命周期**：按需创建，长期保持
- **功能**：支持工具审核流程
- **权限控制**：仅管理员可访问

**使用流程说明**：

审核容器的完整使用流程：
1. 管理员提交审核任务
2. 获取审核容器连接信息
3. 若不可用，自动创建或恢复
4. 部署待审核工具
5. 执行审核测试
6. 清理审核环境（可选）
7. 容器保持就绪状态

### 6. 端口管理与网络配置

#### 6.1 端口分配

**端口范围**：30000-40000

**分配策略**：
- **动态分配**：从指定范围随机选择可用端口
- **冲突检测**：分配前检测端口是否已被占用
- **持久化**：端口信息存储在数据库，容器重启后保持不变

**端口使用场景**：
- **内部端口**：容器内部服务端口（默认 8080）
- **外部端口**：映射到宿主机的访问端口（动态分配）
- **访问方式**：通过容器 IP:外部端口访问服务

#### 6.3 安全隔离

**网络隔离**：
- 每个容器拥有独立的网络命名空间
- 容器间默认无法互相访问，除非显式配置
- 禁止使用 privileged（特权）模式运行容器

**文件系统隔离**：
- 每个用户容器挂载独立的数据卷
- 数据卷路径：/data/users/{userId}
- 审核容器使用独立的数据卷路径：/data/review

**安全加固要求**：
- 启用 Docker seccomp 安全配置文件
- 启用 AppArmor 或 SELinux 强制访问控制
- 限制容器的 Linux capabilities（如 CAP_NET_BIND_SERVICE、CAP_SYS_ADMIN）
- 禁止挂载敏感主机目录（如/etc、/proc、/sys）
- 只读挂载系统文件，防止容器逃逸

### 7. 容器模板管理

#### 7.1 MCP 网关模板

**默认镜像**：`ghcr.io/lucky-aeon/mcp-gateway:latest`

**模板配置说明**:
- 镜像：ghcr.io/lucky-aeon/mcp-gateway:latest
- 内部端口：8080
- CPU 限制：1.0 核
- 内存限制：512 MB
- 网络模式：bridge
- 重启策略：unless-stopped

**功能特性**：
- **统一标准**：所有用户容器使用相同的镜像和配置
- **快速部署**：基于模板快速创建容器
- **可扩展性**：支持自定义模板配置

#### 7.2 容器配置

**环境变量**：
- 支持自定义环境变量配置（JSON 格式存储）
- 可根据业务需求动态注入配置

**数据卷挂载**：
- 用户数据卷: `/data/users/{userId}`
- 持久化用户数据，容器重启后保留

**命令参数**：
- 支持自定义容器启动命令
- 支持传递命令行参数

### 8. 容器操作接口

#### 8.1 用户接口

**获取用户容器**
- 接口路径：GET /api/containers/user
- 功能说明：自动处理容器不存在和异常情况，返回可用的容器信息

**创建用户容器**
- 接口路径：POST /api/containers/user
- 功能说明：手动触发容器创建，返回新创建的容器信息

**检查容器健康**
- 接口路径：GET /api/containers/user/health
- 功能说明：执行全面健康检查，返回健康检查结果

#### 8.2 管理员接口

**容器列表查询**
- 接口路径：GET /admin/containers
- 功能说明：分页查询所有容器，支持按类型、状态筛选

**容器统计信息**
- 接口路径：GET /admin/containers/statistics
- 功能说明：按状态统计容器数量，按类型统计容器数量，计算平均资源使用率

**容器操作接口**：
- POST /admin/containers/review - 创建审核容器
- POST /admin/containers/{id}/start - 启动容器
- POST /admin/containers/{id}/stop - 停止容器
- DELETE /admin/containers/{id} - 删除容器

## 使用场景

### 场景 1：用户首次使用 Agent 对话

**流程描述**：
1. 用户登录 AgentX 平台
2. 首次发起 Agent 对话请求
3. 系统调用 `getUserContainer(userId)` 获取用户容器
4. 容器不存在，自动调用 `createUserContainer(userId)` 创建
5. 基于 MCP 网关模板创建容器，分配端口和数据卷
6. 启动容器并初始化环境
7. 返回容器连接信息
8. 对话流程正常进行

**关键能力**：
- 容器按需创建
- 自动端口分配
- 数据卷挂载
- 容器模板应用

### 场景 2：容器异常自动恢复

**流程描述**：
1. 用户发起对话请求
2. 系统调用 `getUserContainer(userId)` 获取容器
3. 执行健康检查，发现容器异常（Docker 容器未运行）
4. 触发智能恢复流程 `recoverUserContainer(container, userId)`
5. 尝试启动已存在的 Docker 容器
6. 更新容器网络信息和状态
7. 容器恢复成功，返回可用信息
8. 对话流程继续进行，用户无感知

**关键能力**：
- 健康检查机制
- 智能恢复策略
- 自动状态同步

### 场景 3：容器资源自动清理

**流程描述**：
1. 用户长期未使用容器（超过 24 小时）
2. 每小时执行的清理任务检测到容器空闲
3. 停容器的 Docker 容器，更新状态为 SUSPENDED
4. 用户再次访问时，自动唤醒容器
5. 若用户长期未使用（超过 5 天）
6. 清理任务删除容器，更新状态为 DELETED
7. 用户数据卷保留待手动清理

**关键能力**：
- 定时任务调度
- 自动清理策略
- 状态优雅转换

### 场景 4：管理员审核工具

**流程描述**：
1. 用户提交工具审核请求
2. 管理员进入工具审核流程
3. 调用 `getReviewContainerConnection()` 获取审核容器
4. 系统自动检查审核容器是否可用
5. 若不可用，自动创建或恢复审核容器
6. 在审核容器中部署待审核工具
7. 执行工具测试验证
8. 完成审核，清理测试环境
9. 审核容器保持就绪状态供下次使用

**关键能力**：
- 审核容器管理
- 健康检查与恢复
- 安全隔离环境

## 功能特性总结

### 核心特性

1. **自动创建**：按需自动创建容器，无需手动配置
2. **智能恢复**：自动检测异常并恢复，提升稳定性
3. **自动清理**：基于策略自动清理闲置容器，优化资源
4. **健康监控**：多维度实时监控容器状态和资源
5. **类型隔离**：用户容器和审核容器完全隔离
6. **网络管理**：自动端口分配和网络配置
7. **数据持久化**：数据卷持久化，容器重启不丢失数据
8. **模板化部署**：基于标准模板快速部署容器

### 性能特性

1. **按需资源**：仅在需要时创建容器，避免资源浪费
2. **弹性伸缩**：根据用户访问量和使用时间动态调整
3. **快速恢复**：容器异常时快速恢复，最小化业务影响
4. **资源限制**：通过 CPU 和内存限制防止单容器占用过多资源

### 安全特性

1. **用户隔离**：不同用户的容器相互隔离
2. **权限控制**：容器操作权限严格控制
3. **审核隔离**：审核容器与用户环境完全隔离
4. **数据隔离**：用户数据独立存储，互不干扰

## 性能要求

### 响应时间指标

- **容器创建时间**: 正常情况小于 30 秒 (包括镜像拉取)
- **容器启动时间**: 从停止状态启动小于 5 秒
- **健康检查响应**: 单次健康检查小于 3 秒
- **智能恢复时间**: 异常容器恢复小于 60 秒

### 资源使用指标

- **CPU 使用率**: 单容器平均 CPU 使用率不超过 50%
- **内存使用率**: 单容器内存使用不超过配置限额的 90%
- **端口分配成功率**: 大于 99.9%
- **容器创建成功率**: 大于 98%

### 并发能力

- **最大并发容器数**: 支持至少 1000 个容器同时运行
- **并发创建速率**: 支持每分钟创建至少 50 个容器
- **监控采集频率**: 资源数据采集间隔不超过 2 分钟
- **状态检查频率**: 容器状态检查间隔不超过 5 分钟

## 安全要求

### 容器隔离

- **命名空间隔离**: 每个容器使用独立的 PID、网络、文件系统命名空间
- **用户命名空间**: 启用用户命名空间重映射，防止特权提升
- **网络隔离**: 容器间默认网络隔离，仅允许通过显式配置的网络通信

### 安全加固

- **Seccomp 配置文件**: 所有容器必须启用 seccomp 安全配置文件
- **AppArmor/SELinux**: 启用强制访问控制配置文件
- **Capabilities 限制**: 删除不必要的 Linux capabilities，禁止使用 CAP_SYS_ADMIN
- **只读文件系统**: 根文件系统默认只读，仅挂载必要的可写卷

### 防逃逸机制

- **禁止特权容器**: 严禁使用 --privileged 参数运行容器
- **敏感目录保护**: 禁止挂载主机敏感目录 (/etc、/proc、/sys、/root 等)
- **设备访问限制**: 禁止访问主机设备文件 (/dev 下的设备)
- **内核调用过滤**: 通过 seccomp 过滤危险的内核调用

### 认证与授权

- **API 访问控制**: 容器操作 API 需要 JWT 认证
- **权限分离**: 用户只能操作自己的容器，管理员可操作所有容器
- **审核日志**: 所有容器操作记录审计日志，保留至少 90 天

### 网络安全

- **端口随机化**: 外部端口随机分配，避免 predictable port 攻击
- **HTTPS 通信**: 容器与宿主机之间的 API 通信使用 HTTPS
- **防火墙规则**: 配置 iptables 规则限制容器网络访问范围

## 可扩展性要求

### 接口扩展

- **容器类型接口**: 支持自定义新的容器类型，无需修改核心代码
- **存储驱动接口**: 支持不同的存储驱动 (overlay2、aufs、zfs 等)
- **网络驱动接口**: 支持不同的网络插件 (bridge、macvlan、ipvlan 等)

### 集群扩展

- **多节点部署**: 支持跨多个 Docker 节点的容器部署
- **负载均衡**: 支持容器服务的负载均衡和故障转移
- **资源调度**: 支持基于节点资源的智能容器调度

### 监控扩展

- **指标采集器**: 支持自定义资源采集器 (GPU、TPU 等特殊资源)
- **告警规则**: 支持自定义监控告警规则和通知渠道
- **数据导出**: 支持将监控数据导出到 Prometheus、Grafana 等平台

## 约束与限制

### 容器数量限制

- **用户容器**：每个用户最多 1 个
- **审核容器**：全系统 1 个

### 资源限制

- **CPU**：默认 1.0 核/容器（可配置）
- **内存**：默认 512 MB/容器（可配置）
- **端口范围**：30000-40000（可配置）
- **磁盘空间**：单容器数据卷不超过 10GB（可配置）

### 使用限制

- **端口分配**：端口随机分配，暂不支持指定端口
- **容器类型**：仅支持 USER 和 REVIEW 两种类型
- **镜像来源**：使用预定义的 MCP 网关镜像，暂不支持自定义镜像
- **网络模式**：统一使用 bridge 模式，暂不支持 host 或 none 模式

### 环境依赖

- **Docker 版本**：要求 Docker Engine 20.10 或更高版本
- **操作系统**：支持 Linux (Ubuntu 20.04+, CentOS 8+)、Windows Server 2019+
- **硬件要求**：
  - 最低 2 核 CPU、4GB 内存
  - 推荐 4 核 CPU、8GB 内存以上
  - 需要启用虚拟化支持

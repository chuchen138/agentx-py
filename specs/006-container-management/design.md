# 容器管理技术设计

## 概述

容器管理模块基于 Docker Container API 和领域驱动设计（DDD）架构实现，采用分层设计模式，将 Docker 基础设施操作、领域业务逻辑和应用层用例清晰分离。

## 技术架构

### 架构分层

系统采用四层架构：表示层（REST API/管理界面）提供外部访问接口；应用层协调用例逻辑，包含容器管理、监控和清理服务；领域层封装核心业务逻辑，管理容器实体和模板；基础设施层对接 Docker Engine 和数据库。

### 设计原则

系统遵循领域驱动设计、依赖倒置、分层清晰、单一职责和开闭原则，确保各层职责明确、扩展灵活。

## 容器类型策略

### 容器类型

系统定义两种容器类型：USER 容器（用户容器）和 REVIEW 容器（审核容器）。

### 用户容器策略

每个用户最多拥有一个容器，容器与用户长期绑定，支持用户对话和工具部署，使用独立端口和数据卷确保数据隔离。容器命名规则为 `mcp-gateway-user-{userId的前8位}`，端口范围 30000-40000，数据卷路径为 `/data/users/{userId}`。

### 审核容器策略

系统仅保留一个审核容器，长期保持就绪状态用于工具审核和测试，仅管理员可访问。容器名称固定为 `mcp-gateway-review`，端口范围 30000-40000，数据卷路径为 `/data/review`。

## 容器状态管理

### 容器状态枚举

容器状态包括：CREATING（创建中）、RUNNING（运行中）、STOPPED（已停止）、ERROR（错误状态）、DELETING（删除中）、DELETED（已删除）、SUSPENDED（已暂停）。

### 状态流转规则

状态机定义严格的状态转换路径，包括创建流程（创建成功/失败）、用户操作流程（启动/停止/唤醒/删除）、系统流程（异常检测/删除完成/重建）。

关键流转规则：CREATING 可转换到 RUNNING 或 ERROR；RUNNING 可转换到 STOPPED、SUSPENDED、ERROR 或 DELETING；STOPPED 可转换到 RUNNING 或 DELETING；SUSPENDED 可转换到 RUNNING 或 DELETING；ERROR 可转换到 RUNNING 或 DELETING；DELETING 可转换到 DELETED。

## 监控与恢复

### 监控指标体系

监控维度包括容器状态（生命周期状态）、Docker 状态（实际运行状态）、资源使用（CPU/内存使用率）、网络状态（IP 地址和端口）、访问记录（最后访问时间）。采集频率从实时到 5 分钟不等。

### 定时任务监控

容器状态检查任务每 5 分钟执行一次，负责检查 Docker 容器状态和运行情况，并同步数据库状态。资源监控任务每 2 分钟执行一次，采集 CPU/内存使用率并更新数据库统计信息。

### 智能恢复机制

恢复策略根据异常类型选择不同方案：Docker 容器存在但未运行时强制启动；容器运行但状态不同步时同步状态；Docker 容器不存在时重建容器；网络信息异常时重新获取；无法恢复的严重错误标记为 ERROR。

恢复流程包括：检查并启动存在的 Docker 容器、同步运行中的容器网络信息、重建不存在的容器、标记恢复失败的容器。优化策略包括快速失败检测、增量恢复（重启 > 同步 > 重建）、并行尝试、缓存利用和超时控制。

## 端口与网络

端口分配算法在 30000-40000 范围内随机生成，检查数据库和系统占用。Docker 网络采用桥接模式，支持端口映射、重启策略、数据卷挂载、资源限制和环境变量配置，并通过 Socket 检测网络连通性。

## 容器模板

容器模板定义配置规范，包括镜像、内部端口、CPU 和内存限制、环境变量、数据卷、启动命令、网络模式和重启策略。系统默认提供 MCP 网关模板，使用 8080 内部端口、1 核 CPU、512 MB 内存、bridge 网络模式和 unless-stopped 重启策略。

## 数据模型

容器实体容器信息包括容器名称、用户 ID、类型（USER 或 REVIEW）、状态、Docker 容器 ID、镜像、内部端口、外部端口、IP 地址、CPU 使用率、内存使用率、数据卷路径、环境配置、容器配置、错误信息和最后访问时间。容器模板独立存储配置模板。

## 定时任务

容器监控任务包括状态检查（每 5 分钟）和资源监控（每 2 分钟）。容器清理任务采用自动清理策略，暂停 1 天未使用的容器，删除 5 天未使用的容器。

## 应用服务

容器应用服务提供用户容器管理（创建、获取、停止、删除）、审核容器管理（获取或创建）、容器操作（启动、停止、删除）、容器查询（分页查询、按 ID 查询）和统计信息功能。

## 异常处理

系统定义完善的异常体系，包括容器不存在、已存在、状态异常、操作失败、Docker 连接失败、容器恢复失败和资源分配失败等异常类型，并提供相应的全局异常处理器。

## 性能优化

性能优化策略包括 Docker 客户端连接池管理、容器信息缓存和异步容器操作。

## 监控与日志

日志规范包括 ERROR（系统错误）、WARN（潜在问题、恢复信息）、INFO（重要业务操作）和 DEBUG（调试信息）。关键监控指标包括容器创建成功率、容器恢复成功率和运行中容器数量。

## 安全考虑

权限控制限制容器操作为管理员或拥有者，资源防滥用通过单用户容器数量限制实现。

## 扩展性

系统支持可扩展的容器类型和可插拔的资源采集器。容器类型接口允许自定义容器名称生成、模板获取和验证逻辑，资源采集器接口支持按类型注册和调用。

## 技术栈

技术栈包括 Docker Engine API（容器管理）、Spring Boot（应用框架）、MyBatis Plus（数据持久化）、H2 Database（数据存储）、SLF4J + Logback（日志管理）、Micrometer + Prometheus（指标监控）、Spring Scheduling（定时任务）和 Spring Cache（缓存管理）。

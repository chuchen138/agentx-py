# 智能体管理技术设计

## 概述

智能体管理模块基于领域驱动设计（DDD）分层架构实现，采用清晰的分层设计模式，将智能体实体、版本管理、工作空间和 Widget 功能清晰分离，确保业务逻辑的清晰性和代码的可维护性。

## 技术架构

### 架构分层

系统采用四层架构：表示层提供接口层和 DTO 定义，处理 HTTP 请求；应用层提供应用服务、组装器和 DTO，负责业务流程编排；领域层提供实体、仓储和领域服务，封装核心业务逻辑；基础设施层提供仓储实现和数据库支持。

## 领域模型

### 核心领域模型

### AgentEntity

智能体实体是智能体管理聚合的根实体，包含智能体 ID、名称、头像、描述、系统提示词、欢迎消息、关联的工具 ID 列表、关联的知识库 ID 列表、工具预设参数、当前发布的版本 ID、是否启用、是否支持多模态和创建者用户 ID 等字段。

### AgentVersionEntity

版本实体记录智能体版本信息，包含版本 ID、关联的 Agent ID、Agent 名称快照、版本号、系统提示词快照、工具列表快照、变更日志、发布状态、审核拒绝原因和发布时间等字段。发布状态包括审核中、已发布、拒绝和已下架。

### AgentWidgetEntity

Widget 实体管理智能体 Widget 配置，包含 Widget ID、关联的 Agent ID、公开访问 ID、Widget 名称、使用模型 ID、允许的域名列表、每日调用限制和 Widget 类型等字段。

### LLMModelConfig

LLM 模型配置值对象包含模型 ID、温度参数、Top P 参数、最大 Token 数和 Token 溢出策略等配置。

## 状态机设计

### 版本发布状态机

版本发布状态机定义状态转换规则，从初始状态创建新版本时设置为审核中，审核中状态可转换到已发布（管理员审核通过）或拒绝（管理员审核拒绝），已发布状态可转换到已下架（管理员下架操作）。

## 数据模型

### 数据表

智能体表包含 ID、名称、描述、系统提示词、工具 ID 列表（JSON）、知识库 ID 列表（JSON）和创建者用户 ID 等字段。版本表包含版本 ID、Agent ID、版本号、变更日志和发布状态等字段。

## 服务分层设计

### 应用层职责

应用层接收和验证来自接口层的请求，调用领域服务执行业务逻辑，协调多个领域服务的交互，转换领域对象为 DTO。

### 领域层职责

领域层封装核心业务逻辑，定义领域模型和业务规则，提供领域服务接口。

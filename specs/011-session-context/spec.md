# 会话上下文（Session Context）

## 概述

会话上下文模块负责管理系统的对话会话，包括会话生命周期管理、上下文维护、历史消息存储和 Token 策略控制等核心功能。

## 功能需求

### 1. 会话管理

**描述**：管理用户对话的整个生命周期，包括会话创建、激活、中断和销毁。

**功能**：
- **会话注册**：创建新的对话会话，分配会话 ID
- **会话中断**：支持用户主动中断当前对话
- **会话查询**：根据会话 ID 查询会话状态
- **会话状态管理**：会话状态包括活跃、完成、超时、错误

**要求**：
- 支持会话的并发管理
- 支持会话超时自动清理
- 支持会话中断后的资源释放
- 会话信息实时更新

### 2. 上下文维护

**描述**：维护对话的上下文信息，确保对话的连贯性和一致性。

**功能**：
- **上下文构建**：根据历史消息构建当前上下文
- **上下文更新**：每次交互后更新上下文
- **上下文版本管理**：保存上下文的多个版本
- **上下文恢复**：从历史版本恢复上下文

**要求**：
- 上下文包含用户消息、系统消息和 Assistant 回复
- 上下文支持会话间隔离
- 支持上下文的增量更新

### 3. Token 策略

**描述**：控制对话的 Token 使用，防止超出模型的限制，管理 Token 分配和策略。

**功能**：
- **Token 计算**：计算消息和上下文的 Token 占用
- **Token 限制**：根据模型限制设置最大 Token 数量
- **Token 溢出处理**：当超过限制时采取策略（截断、压缩、摘要）
- **Token 策略配置**：支持配置不同的 Token 限制和策略

**策略类型**：
- **截断策略**：截断最早的消息
- **摘要策略**：对早期消息进行摘要压缩
- **动态窗口策略**：根据内容重要性动态调整窗口

**要求**：
- 支持不同模型的不同 Token 限制
- 提供准确的 Token 计算
- Token 使用统计和监控

### 4. 历史消息管理

**描述**：存储和管理对话的历史消息，支持消息的查询和检索。

**功能**：
- **消息存储**：保存每次交互的消息
- **消息查询**：查询会话的历史消息
- **消息分页**：支持大量消息的分页查询
- **消息过滤**：按角色、时间等过滤消息

**要求**：
- 消息按时间顺序存储
- 支持消息的实时追加
- 支持消息的高效查询

### 5. 会话实时通信

**描述**：使用 Server-Sent Events (SSE) 实现会话的实时通信。

**功能**：
- **SSE 连接建立**：为每个会话建立 SSE 连接
- **实时消息推送**：将 AI 回复实时推送给客户端
- **连接管理**：管理活跃的 SSE 连接
- **连接清理**：连接完成、超时、错误时清理资源

**要求**：
- 支持并发连接
- 连接状态持久化
- 异常情况下的自动重连
- 连接超时和超限处理

### 6. 会话监控和统计

**描述**：统计和监控会话的使用情况，提供给运营分析。

**统计维度**：
- 会话数量统计（按时间、类型）
- 会话时长分布
- 消息数量统计
- Token 使用统计

**要求**：
- 支持实时统计和历史统计
- 支持按用户、时间段等维度统计
- 提供统计 API

## 范围边界

### 与记忆管理 (012) 的边界

- **职责划分**:本模块负责短期会话上下文维护，记忆模块负责长期记忆存储和检索
- **优先级**:会话上下文优先于长期记忆，Token 不足时先压缩会话历史，再考虑加载长期记忆
- **数据流转**:会话结束后，重要信息可异步同步到记忆模块
- **冲突处理**:当会话上下文与长期记忆冲突时，以会话上下文为准 (用户最新输入优先)

### 与 RAG(008) 的边界

- **集成点**:RAG 检索结果作为系统消息插入会话上下文
- **优先级**:RAG 检索在会话上下文中进行，不单独占用 Token 预算
- **冲突处理**:RAG 内容与用户输入冲突时，以用户输入为准

### 与 Agent 执行 (014) 的边界

- **上下文传递**:会话上下文传递给 Agent 执行模块，作为对话历史
- **状态同步**:Agent 执行状态实时反馈到会话状态

## 技术约束

- **SSE 实现**:使用 FastAPI 的 StreamingResponse 或 Starlette 的 EventSourceResponse 实现 SSE 推送
- **会话存储**:活跃会话存储在内存中，使用 Redis 实现分布式会话共享和 pub/sub 消息同步
- **Token 计算**:支持 tiktoken(GPT 系列) 和 Anthropic SDK(Claude 系列),提供降级方案
- **多实例部署**:通过 Redis 实现跨节点会话同步，支持负载均衡
- **上下文长度**:默认最大支持 128K tokens(根据模型窗口动态调整)
- **消息格式**:SSE 事件采用 JSON 格式，包含 event、data、id 字段

## 性能要求

- **会话注册延迟**: < 50ms (P95, 单节点 16C32G 配置)
- **消息推送延迟**: < 100ms (P95, 同地域网络环境)
- **并发会话数**:单节点支持 10000+ 在线会话，集群支持线性扩展
- **历史消息查询**:响应时间 < 200ms (P95, 100 条消息以内)
- **Token 计算速度**: > 1000 tokens/ms (使用缓存的情况下)
- **SSE 连接建立**: < 30ms (P95)
- **心跳检测**:每 30 秒发送一次心跳，超时 90 秒自动断开
- **最大上下文长度**:不超过模型窗口的 80% (预留安全余量)

## 安全要求

- **会话认证**:SSE 连接建立时需验证 JWT Token 或 API Key，防止未授权访问
- **防 CSRF 攻击**:使用同源策略 + Token 验证双重机制
- **防会话劫持**:session_id 使用加密随机字符串 (至少 32 位),定期刷新
- **连接鉴权**:每次 SSE 重连需重新验证身份，支持 IP 白名单绑定 (可选)
- **敏感信息保护**:用户凭证、密钥等敏感数据不存储在会话中，日志脱敏处理
- **会话过期清理**:支持 TTL(默认 30 分钟无操作) 和 LRU(内存不足时) 两种清理策略
- **心跳机制**:每 30 秒发送心跳包，检测连接有效性，防止僵尸连接
- **速率限制**:单用户每秒最多创建 5 个会话，防止恶意刷接口
- **审计日志**:记录会话创建、中断、异常等关键事件，保留 90 天

## 可靠性要求

- **会话持久化**:关键会话数据双写到 Redis+MySQL，服务重启后可恢复
- **SSE 断线重连**:支持 last-event-id 机制，客户端可从中断点恢复 (最多重试 3 次)
- **状态一致性**:分布式环境下使用 Redis Lua 脚本保证会话状态原子性更新
- **故障转移**:节点故障时，通过 Redis 哨兵模式自动切换到备用节点
- **备份恢复**:支持会话数据定时备份 (每小时),支持按时间点恢复
- **降级策略**:Redis 不可用时降级到纯内存模式，告警并限制部分功能
- **消息确认**:重要消息支持 ACK 机制，确保客户端收到
- **异常恢复**:SSE 连接异常时自动清理资源，记录详细错误日志

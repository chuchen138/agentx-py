# 会话上下文技术设计

## 概述

会话上下文模块使用会话管理器（ChatSessionManager）作为核心组件，结合 SSE 实现实时通信。

## 架构设计

### 整体架构

系统采用 ChatSessionManager 管理活跃对话会话，结合 SSE 推送实时消息，可选择性将会话数据持久化到数据库。

### 核心组件

ChatSessionManager 负责管理当前活跃的所有对话会话，维护会话状态和 SSE 连接，处理会话的注册、中断和清理，向客户端推送实时消息。使用 ConcurrentHashMap 存储会话（线程安全），提供会话生命周期管理。

会话数据模型包括 SessionEntity（会话 ID、用户 ID、会话状态、创建时间、更新时间、关联的 Agent 信息）、MessageEntity（消息 ID、会话 ID、角色、消息内容、创建时间、Token 数量）和 ContextEntity（上下文 ID、会话 ID、上下文内容、版本号、创建时间）。

## 设计模式

### 会话管理器模式

集中管理所有活跃会话，提供统一的会话操作接口。ChatSessionManager 作为单例管理器，使用 ConcurrentHashMap 存储会话实现线程安全，提供会话生命周期管理。

### 观察者模式

SSE 连接的生命周期事件通知处理。通过 SseEmitter 的回调（onCompletion, onTimeout, onError）自动清理会话资源。

## 技术实现

### 会话生命周期

创建会话信息并存储到活跃会话中，设置 SSE 完成回调和超时回调，自动清理会话资源。标记会话为中断状态，发送中断事件给客户端，完成 SSE 连接。从活跃会话中移除，持久化会话信息（可选），清理资源。

### SSE 消息推送

查找会话信息，检查会话状态，发送 SSE 事件。如果会话已中断则停止推送，发送失败时自动清理会话。

## Token 管理

### Token 计算

根据模型选择不同的计算策略，包括 GPT-4 和 GPT-3.5-turbo 使用 tiktoken 库精确计算、Claude-3 使用特定计算方法、基于长度估算。

### Token 溢出处理

Token 数量超过限制时，根据策略处理。截断策略包括 FROM_START（从开头截断）、FROM_END（从尾部截断）、IMPORTANT_FIRST（按重要性截断）。摘要策略是对更早的消息进行摘要，保留摘要和重要消息。

## 配置设计

系统支持灵活的会话配置：enabled（是否启用会话管理）、timeout（空闲超时时间、最大会话时长）、sse（重连配置、心跳配置）、storage（存储类型、过期时间）、token（默认限制、溢出策略、计算方法）。

## 关键流程

### 会话建立流程

客户端发起对话请求、生成会话 ID、ChatSessionManager 注册会话、返回会话 ID 和 SSE URL、客户端建立 SSE 连接、会话进入活跃状态。

### 消息推送流程

AI 生成回复、ChatSessionManager 发送消息、客户端接收消息、客户端显示消息、用户继续对话或结束会话。

### 会话中断流程

用户点击停止按钮、调用 /conversation/interrupt、ChatSessionManager 中断会话、清理会话、返回中断成功。

## 错误处理

系统定义完善的异常处理机制：会话不存在返回 404 错误；向已中断的会话发送消息时记录日志；客户端断开连接时自动清理会话；Token 计算接口异常时降级到基于长度的估算。

## 性能优化

内存管理使用 ConcurrentHashMap 保证线程安全，定期清理超时会话，限制最大活跃会话数。SSE 事件批量发送，压缩大消息，使用连接池管理 SSE 连接。缓存文本的 Token 计算结果，避免重复计算，使用 LRU 淘汰策略。

## 监控指标

关键指标包括活跃会话数、会话创建速率、平均会话时长、消息推送延迟、Token 使用量、会话中断率。告警规则包括活跃会话数超过阈值、会话创建速率异常、消息推送延迟过高、Token 使用超标。

# API 密钥管理（API Key Management）能力规范

## 1. 概述

API 密钥管理模块为 AgentX 平台提供完整的 API 密钥生命周期管理能力。通过该模块，用户可以为已创建的 Agent 生成专属的 API 密钥，用于外部系统调用 Agent 的对话能力。模块提供密钥的创建、状态切换、重置、验证、使用统计等功能，确保 API 调用的安全性和可追溯性。

### 1.1 核心定位

- **认证授权**：作为 Agent 外部调用的身份认证手段
- **访问控制**：通过密钥状态管理控制 API 访问权限
- **使用审计**：记录密钥使用情况，支持用量分析
- **安全隔离**：每个密钥关联特定 Agent 和用户，实现权限隔离

### 1.2 目标用户

- **终端用户**：需要为第三方应用授权访问自己 Agent 的用户
- **外部开发者**：需要通过 API 集成 Agent 能力的开发者
- **平台管理员**：监控和管理 API 密钥使用情况

### 1.3 价值主张

提供安全、可靠、易用的 API 密钥管理能力，使 AgentX 平台能够：

- 支持 Agent 能力的开放 API 访问
- 实现 API 调用细粒度的权限控制
- 追踪和分析 API 使用趋势
- 保障 API 调用的安全性

## 2. 核心能力

### 2.1 密钥生成

**能力描述**：为指定的 Agent 生成唯一的 API 密钥。

**功能特性**：
- 支持为任意用户拥有的 Agent 创建 API 密钥
- 密钥格式标准化：`ak_{agentId}_{randomString}`（例如：`ak_agent123_abc123def456ghij`）
- 随机字符串采用 UUID 生成，取前 16 位，确保全局唯一性
- 支持为密钥添加自定义名称/描述，便于管理
- 创建时自动设置为启用状态

**输入参数**：
- Agent ID（必需）
- 密钥名称/描述（必需）

**输出结果**：
- 生成的 API 密钥（仅创建时可见）
- 密钥基本信息（ID、名称、状态等）

### 2.2 密钥查询

**能力描述**：查询和管理用户的 API 密钥列表。

**功能特性**：
- 支持查询当前用户的所有 API 密钥
- 支持按 Agent ID 筛选特定 Agent 的密钥
- 支持按密钥名称模糊搜索
- 支持按启用/禁用状态筛选
- 查询结果按创建时间倒序排列
- 自动关联展示密钥对应的 Agent 名称

**查询维度**：
- 用户维度：获取用户所有密钥
- Agent 维度：获取特定 Agent 的所有密钥
- 单个密钥维度：获取密钥详细信息

**显示信息**：
- 密钥 ID、密钥值（脱敏显示）
- 关联的 Agent 信息（ID、名称）
- 密钥名称/描述
- 密钥状态（启用/禁用）
- 使用统计（已使用次数、最后使用时间）
- 过期信息（过期时间、是否已过期）
- 可用状态（状态和过期时间的综合）
- 时间信息（创建时间、更新时间）

### 2.3 密钥状态管理

**能力描述**：控制 API 密钥的启用和禁用。

**功能特性**：
- 支持随时启用或禁用已创建的 API 密钥
- 禁用的密钥无法通过验证，拒绝 API 调用
- 状态切换即时生效，无需重启服务
- 支持批量操作（通过扩展实现）

**状态类型**：
- **启用（TRUE）**：密钥有效，可用于 API 验证
- **禁用（FALSE）**：密钥无效，拒绝 API 调用

**业务规则**：
- 禁用密钥不影响历史使用记录
- 禁用中的密钥可随时重新启用
- 过期的密钥即使处于启用状态也无法使用

### 2.4 密钥重置

**能力描述**：为已存在的 API 密钥生成新的密钥值。

**功能特性**：
- 保持密钥 ID、关联关系、状态等其他属性不变
- 生成新的密钥值，替换原有密钥
- 重置时清零使用次数和最后使用时间
- 新密钥值仅重置时可见，之后无法再次查看

**使用场景**：
- 原密钥泄露，需要立即更换
- 定期安全轮换，提高安全性
- 密钥遗忘，需要重新生成

**业务规则**：
- 重置后的旧密钥立即失效
- 不影响密钥的状态（启用/禁用）
- 不影响密钥的关联 Agent 和用户

### 2.5 密钥验证

**能力描述**：验证 API 密钥的有效性，并提取关联的用户和 Agent 信息。

**功能特性**：
- 验证密钥是否存在（有效性检查）
- 验证密钥状态是否启用（权限检查）
- 验证密钥是否过期（时效检查）
- 验证通过后自动更新使用统计
- 返回验证结果及关联信息

**验证逻辑**：
```
1. 根据 API Key 值查找记录
2. 如果记录不存在 → 验证失败（无效的 API Key）
3. 如果记录存在：
   - 检查状态是否为启用
   - 检查是否已过期
   - 任一条件不满足 → 验证失败（API Key 已禁用或过期）
4. 验证通过：
   - 增加使用次数
   - 更新最后使用时间
   - 返回用户 ID 和 Agent ID
```

**输出结果**：
- 验证成功：返回用户 ID、Agent ID、验证状态、成功消息
- 验证失败：返回验证状态、失败原因

### 2.6 密钥删除

**能力描述**：永久删除不再使用的 API 密钥。

**功能特性**：
- 支持删除用户拥有的任意 API 密钥
- 删除后密钥无法恢复
- 删除操作需要权限验证（只能删除自己的密钥）
- 建议在删除前先禁用密钥

**业务规则**：
- 删除后该密钥立即失效
- 删除操作不可逆
- 建议提供二次确认机制

### 2.7 使用统计

**功能特性**：
- 自动记录密钥的使用次数
- 记录最后一次使用时间
- 每次验证成功时自动更新统计
- 支持查询历史使用记录（通过扩展实现）

**统计字段**：
- `usage_count`：累计使用次数
- `last_used_at`：最后使用时间戳

### 2.8 过期管理

**功能特性**：
- 支持设置密钥过期时间（预留字段）
- 验证时自动检查是否过期
- 自动计算并返回是否已过期状态
- 过期的密钥即使启用也无法使用

**业务规则**：
- 过期时间可设置为空，表示永不过期
- 过期时间到后无需人工干预，密钥自动失效
- 过期状态通过当前时间与过期时间对比计算

## 3. 使用场景

### 3.1 场景一：Web 应用集成 Agent 对话能力

**场景描述**：用户开发了一个 Web 应用，需要通过 API 调用自己的 Agent 为用户提供对话服务。

**操作流程**：

1. **创建 Agent**：用户在 AgentX 平台创建并配置好 Agent
2. **生成密钥**：为 Agent 创建一个 API 密钥，命名为"Web 应用生产环境密钥"
3. **配置应用**：在 Web 应用配置中使用生成的 API 密钥
4. **API 调用**：Web 应用通过 API 密钥调用 Agent 对话接口
5. **监控使用**：查看密钥的使用统计，监控调用频率

**关键功能**：
- 密钥生成：为 Agent 创建专属密钥
- 密钥验证：验证 Web 应用的 API 调用请求
- 使用统计：监控调用次数和使用频率

### 3.2 场景二：移动应用后端服务集成

**场景描述**：用户开发了一个移动应用，需要在后端服务中集成 Agent 能力，为移动端用户提供智能对话功能。

**操作流程**：

1. **创建密钥**：为 Agent 创建 API 密钥，命名为"移动应用后端密钥"
2. **后端集成**：在移动应用后端服务中配置 API 密钥
3. **请求转发**：移动应用请求后端服务，后端服务使用密钥调用 Agent API
4. **响应返回**：Agent 处理完成后返回对话结果给移动端

**关键功能**：
- 密钥生成和命名：创建可识别的密钥名称
- 密钥验证：验证后端服务的 API 请求
- 使用统计：跟踪移动用户的对话请求量

### 3.3 场景三：第三方系统对接

**场景描述**：企业的现有业务系统需要对接 AgentX 平台的 Agent 能力，实现智能化升级。

**操作流程**：

1. **创建专用密钥**：为 Agent 创建一个专门用于第三方系统对接的密钥
2. **系统配置**：在第三方系统中配置 API 密钥和调用接口
3. **联调测试**：使用密钥进行接口联调测试
4. **上线部署**：密钥设置完成后正式上线使用
5. **权限管理**：通过状态管理控制密钥访问权限

**关键功能**：
- 密钥生成：为第三方系统创建专属密钥
- 密钥验证：验证第三方系统的调用请求
- 状态管理：在维护时临时禁用密钥
- 使用统计：监控第三方系统的调用量

### 3.4 场景四：密钥安全事件处理

**场景描述**：用户发现某 API 密钥可能已泄露，需要立即处理。

**操作流程**：

1. **问题发现**：检测到异常调用或密钥泄露风险
2. **立即禁用**：立即禁用可疑密钥，阻止非法访问
3. **生成新密钥**：为 Agent 创建新的 API 密钥
4. **系统更新**：在调用系统中更新为新密钥
5. **验证测试**：测试新密钥是否正常工作
6. **删除旧密钥**：确认新密钥正常后，删除旧密钥

**关键功能**：
- 密钥禁用：立即阻止非法访问
- 密钥重置：生成新密钥替换旧密钥
- 密钥删除：永久删除不再使用的密钥
- 使用统计：通过异常流量发现安全问题

### 3.5 场景五：定期密钥轮换

**场景描述**：出于安全考虑，企业要求定期更换 API 密钥。

**操作流程**：

1. **制定计划**：提前规划密钥轮换时间表
2. **创建新密钥**：为 Agent 创建新的 API 密钥
3. **系统配置**：在调用系统中添加新密钥配置
4. **灰度切换**：逐步将流量切换到新密钥
5. **禁用旧密钥**：确认新密钥正常后，禁用旧密钥
6. **删除旧密钥**：等待一段时间后，删除旧密钥

**关键功能**：
- 密钥生成：创建新密钥
- 密钥重置：重置密钥值（可选方案）
- 密钥禁用：平滑过渡，不影响业务
- 使用统计：验证新密钥接收正常流量

### 3.6 场景六：多环境密钥管理

**场景描述**：用户需要为开发、测试、生产等不同环境创建不同的 API 密钥。

**操作流程**：

1. **开发环境**：创建名为"开发环境"的密钥，用于开发调试
2. **测试环境**：创建名为"测试环境"的密钥，用于测试验证
3. **预生产环境**：创建名为"预生产环境"的密钥，用于上线前验证
4. **生产环境**：创建名为"生产环境"的密钥，用于正式对外服务
5. **环境隔离**：不同环境使用不同密钥，便于管理
6. **灵活切换**：通过禁用/启用来控制环境访问

**关键功能**：
- 密钥命名：创建可识别的环境名称
- 密钥查询：按环境筛选密钥列表
- 状态管理：通过状态控制环境访问
- 使用统计：分别统计各环境使用情况

### 3.7 场景七：密钥权限追溯

**场景描述**：需要追溯特定 API 调用的来源密钥和关联用户。

**操作流程**：

1. **接收请求**：系统收到 API 调用请求，包含 API Key
2. **验证密钥**：验证 API Key 的有效性
3. **提取信息**：提取密钥关联的用户 ID 和 Agent ID
4. **记录日志**：记录调用日志，包含用户、Agent、密钥信息
5. **问题追溯**：根据日志追溯问题来源

**关键功能**：
- 密钥验证：验证密钥并提取关联信息
- 用户关联：每个密钥关联到创建用户
- Agent 关联：每个密钥关联到特定 Agent
- 使用统计：记录密钥使用轨迹

## 5. 约束条件

### 5.1 功能约束

- 每个密钥必须关联一个已存在的 Agent
- 每个密钥属于创建它的用户，仅创建者可管理
- 密钥值仅创建或重置时可见，创建后无法再次查看明文
- 密钥格式固定为 `ak_{agentId}_{randomString}`，不可自定义
- 删除密钥为永久操作，无法恢复

### 5.2 性能约束

- 密钥验证应在毫秒级响应（< 50ms）
- 密钥列表查询应支持分页（预留）
- 大量密钥场景下查询性能需保持稳定
- 使用统计更新应采用原子操作，避免并发冲突
- 支持 QPS >= 1000 的验证请求

### 5.3 安全约束

- 密钥值应加密存储（通过基础设施层实现）
- 禁止通过查询接口返回密钥明文
- 密钥验证失败时不暴露详细错误信息
- 密钥操作需要用户身份认证
- 密钥生成使用 Python secrets 模块提供加密安全的随机数
- 支持密钥自动过期机制，过期后自动失效
- 支持密钥轮换策略，定期更换密钥提高安全性
- 审计日志持久化到数据库，记录所有关键操作

### 5.4 业务约束

- 用户只能查看和管理自己创建的密钥
- 同一个 Agent 可创建多个密钥
- 同一个密钥只能关联一个 Agent
- 密钥重置后旧密钥立即失效

## 6. 非功能需求

### 6.1 可用性

- 密钥验证服务应 7x24 小时可用
- 密钥状态切换应实时生效
- 服务故障时应提供降级方案

### 6.2 可靠性

- 密钥存储不应丢失
- 使用统计数据应准确无误
- 并发场景下统计数据更新应正确

### 6.3 可扩展性

- 支持未来扩展密钥过期时间配置
- 支持未来扩展密钥访问频率限制
- 支持未来扩展密钥 IP 白名单限制
- 支持未来扩展多种密钥类型（如只读密钥、管理员密钥）
- 支持未来扩展密钥权限分级（不同密钥拥有不同操作权限）

### 6.4 可观测性

- 关键操作应记录操作日志（创建、删除、重置、状态变更）
- 密钥验证失败应记录日志用于安全审计
- 密钥使用统计应支持查询和分析

## 7. 未来演进方向

### 7.1 近期规划

- **密钥过期时间配置**：支持为密钥设置过期时间，增强安全性
- **使用频率限制**：对密钥的调用频率进行限制，防止滥用
- **密钥标签管理**：为密钥添加标签，便于分类管理

### 7.2 中期规划

- **IP 白名单**：限制密钥只能在指定 IP 地址使用
- **密钥历史记录**：记录密钥的所有操作历史，便于审计
- **批量操作**：支持批量启用、禁用、删除密钥

### 7.3 远期规划

- **密钥权限细分**：支持为不同密钥设置不同的权限级别
- **访问令牌（JWT）**：支持基于 JWT 的临时令牌
- **多维统计分析**：提供更丰富的密钥使用统计和分析功能

## 8. 相关模块

### 8.1 依赖模块

- **Agent 管理**：密钥必须关联已存在的 Agent，创建密钥时需验证 Agent 所有权
- **用户管理**：密钥关联用户 ID，需要用户身份认证
- **会话管理**：密钥验证通过后调用 Agent 对话能力，验证结果包含用户 ID 和 Agent ID

### 8.2 协作模块

- **认证授权**：密钥验证是认证授权的重要组成部分，通过中间件实现
- **监控告警**：密钥使用异常时触发监控告警（如频繁验证失败、异常高频调用）
- **日志审计**：密钥操作和验证记录进入审计日志，持久化到数据库

## 9. 术语表

| 术语 | 解释 |
|-----|------|
| API 密钥 | 用于认证和授权 Agent API 访问的唯一标识符 |
| Agent | AgentX 平台中的智能对话代理实体 |
| 密钥启用 | 密钥处于可用状态，可通过验证 |
| 密钥禁用 | 密钥处于不可用状态，拒绝验证 |
| 密钥重置 | 为已有密钥生成新的密钥值 |
| 密钥验证 | 验证密钥的有效性并提取关联信息 |
| 使用次数 | 密钥累计被成功验证的次数 |
| 过期时间 | 密钥可选的过期时间，到期后自动失效 |
| Agent ID | Agent 的唯一标识符 |
| 用户 ID | 用户的唯一标识符 |
| 熵值 | 随机数的不确定性度量，密钥生成应使用 >= 128 位熵值 |
| QPS | Queries Per Second，每秒查询率 |

## 10. 附录：示例流程

### 10.1 创建 API 密钥示例

**请求**：
```http
POST /api/v1/api-keys
Content-Type: application/json
Authorization: Bearer <user_token>

{
  "agent_id": "agent_123",
  "name": "生产环境密钥"
}
```

**响应**（201 Created）：
```json
{
  "id": "apikey_abc123",
  "api_key": "ak_agent_123_a3f5c8d9e2b1f4a6",
  "agent_id": "agent_123",
  "agent_name": "客服助手",
  "user_id": "user_456",
  "name": "生产环境密钥",
  "status": true,
  "usage_count": 0,
  "last_used_at": null,
  "expires_at": null,
  "is_expired": false,
  "is_available": true,
  "created_at": "2024-01-01T00:00:00Z",
  "updated_at": "2024-01-01T00:00:00Z"
}
```

**注意**：`api_key` 字段仅在创建时返回一次，后续无法查看明文。

### 10.2 使用 API 密钥调用 Agent 示例

**请求**：
```http
POST /api/v1/chat/completions
Content-Type: application/json
X-API-Key: ak_agent_123_a3f5c8d9e2b1f4a6

{
  "message": "你好，请介绍一下你自己"
}
```

**验证流程**：
1. 系统从 `X-API-Key` 请求头提取密钥值
2. 查询数据库验证密钥是否存在
3. 检查密钥状态是否为启用（true）
4. 检查密钥是否已过期（当前时间 < expires_at）
5. 验证通过，更新使用统计（usage_count + 1, last_used_at = now）
6. 提取密钥关联的 user_id 和 agent_id
7. 使用该 agent_id 调用 Agent 对话能力

**响应**（200 OK）：
```json
{
  "message": "你好！我是 AgentX 平台的智能助手...",
  "usage": {
    "tokens": 100
  }
}
```

### 10.3 密钥轮换示例

**场景**：定期安全轮换密钥

**步骤**：

1. **创建新密钥**
   ```bash
   POST /api/v1/api-keys
   {"agent_id": "agent_123", "name": "生产环境密钥 -2024Q1"}
   
   # 返回新密钥：ak_agent_123_new_random_string
   ```

2. **更新系统配置**
   在调用系统中将旧密钥替换为新密钥

3. **灰度测试**
   使用新密钥进行少量请求测试

4. **禁用旧密钥**
   ```bash
   PUT /api/v1/api-keys/old_key_id/status
   {"status": false}
   ```

5. **监控验证**
   确认新密钥正常工作，无异常日志

6. **删除旧密钥**
   ```bash
   DELETE /api/v1/api-keys/old_key_id
   ```

### 10.4 密钥泄露应急处理示例

**场景**：检测到密钥异常调用

**应急响应流程**：

1. **立即禁用可疑密钥**
   ```bash
   PUT /api/v1/api-keys/compromised_key_id/status
   {"status": false}
   ```
   立即生效，阻止非法访问

2. **查看使用记录**
   ```bash
   GET /api/v1/api-keys/compromised_key_id
   # 查看 usage_count 和 last_used_at，分析异常行为
   ```

3. **创建新密钥**
   ```bash
   POST /api/v1/api-keys
   {"agent_id": "agent_123", "name": "紧急轮换密钥"}
   ```

4. **更新应用配置**
   在合法应用中快速切换到新密钥

5. **删除泄露密钥**
   ```bash
   DELETE /api/v1/api-keys/compromised_key_id
   ```

6. **安全审计**
   - 查看审计日志，追溯泄露原因
   - 评估影响范围
   - 必要时通知相关用户

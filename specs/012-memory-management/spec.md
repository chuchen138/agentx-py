# 记忆管理（Memory Management）能力规范

## 概述

记忆管理模块为 AgentX 系统提供长期记忆存储、检索、去重和重要性加权功能。该模块通过自动抽取对话中的有价值信息，结合向量相似度检索和重要性评分机制，实现对用户的偏好、目标、事实和情景信息的智能化管理，显著提升多轮对话的连贯性和个性化体验。

## 核心能力

### 1. 长期记忆存储

**功能描述**：将用户对话中的关键信息自动抽取并持久化存储，支持跨会话的长期记忆保持。

**核心特性**：
- 自动提取：从对话内容中智能识别并提取有价值的记忆点
- 类型分类：将记忆按照性质分为四种类型（PROFILE/TASK/FACT/EPISODIC）
- 重要性评分：为每条记忆分配 0.0-1.0 的分数，用于写入阈值和读取加权
- 标签体系：支持记忆标签的添加和管理，便于筛选和分类
- 元数据存储：提供灵活的数据字段（JSONB），支持结构化负载

### 2. 记忆检索

**功能描述**：基于查询内容的语义相似度和记忆重要性，智能召回最相关的记忆条目。

**核心特性**：
- 向量相似度检索：使用用户专属的嵌入模型进行语义匹配
- 重要性加权：综合计算相似度分值和重要性分值，提升检索质量
- 多租户隔离：严格按用户级别隔离记忆数据和检索范围
- 自定义 Top-K：支持灵活调整召回条目数量
- 状态过滤：仅返回活跃状态的记忆记录

### 3. 去重/合并

**功能描述**：通过语义哈希机制实现记忆的去重和智能合并，避免重复信息积累。

**核心特性**：
- 语义去重：对记忆文本进行标准化处理，生成 SHA-256 哈希值
- 幂等写入：对相同内容的记忆进行合并而非重复创建
- 智能合并策略：
  - 重要性取最大值
  - 标签合并去重
  - 文本选用更丰富版本
  - 数据字段智能合并

### 4. 记忆管理

**功能描述**：提供记忆条目的增删查改管理界面，支持用户对个人记忆的完整控制。

**核心特性**：
- 分页查询：支持按类型分页浏览记忆列表
- 手动创建：允许用户手动添加记忆条目
- 归档删除：支持记忆的软删除（归档）操作
- 类型过滤：支持按记忆类型筛选显示

## 记忆类型

### PROFILE（用户偏好）

**定义**：用户稳定的偏好、人格特质或固定的格式要求。

**示例**：
- "以后都用简体中文回答"
- "回答尽量附带 bash 示例"
- "输出格式要求 JSON"

**适用场景**：
- 用户明确表达的交互偏好
- 固定的输出格式要求
- 持续性的语言或风格偏好

### TASK（目标任务）

**定义**：明确的中长期目标或持续性计划。

**示例**：
- "一周内完成 Agent 项目并补齐文档"
- "这个月学习 Python 基础"
- "目前正在重构旧系统的用户模块"

**适用场景**：
- 用户陈述的中长期目标
- 正在进行的持续任务
- 有明确时间框架的计划

### FACT（稳定事实）

**定义**：与用户身份或工作环境相关的、在较长时间内稳定不变的事实。

**示例**：
- "主要编程语言是 Python"
- "平时在上海办公"
- "公司名称是 X Tech"

**适用场景**：
- 用户的基本信息
- 工作环境相关事实
- 技能栈背景信息

### EPISODIC（情景信息）

**定义**：未来 3-5 轮交互内明显有帮助的情节性信息。

**示例**：
- "刚才我们讨论了 Kafka 消息队列的配置"
- "上一步配置了 API 密钥"
- "之前提到了 Spring Boot 的版本"

**适用场景**：
- 短期内的上下文关联
- 跨轮次的信息引用
- 临时但有价值的情节

## 使用场景

### 场景一：个性化对话体验

**描述**：用户在使用 Agent 进行多轮对话时，系统能够记住用户的偏好和上下文，提供个性化的响应。

**用户工作流**：
1. 用户首次表达偏好："以后都用中文回答，尽量详细一些"
2. 系统自动提取并保存为 PROFILE 类型记忆
3. 后续对话中，系统自动召回该偏好记忆
4. 系统在生成回复时，自动应用该偏好设置

**价值体现**：
- 提升用户体验的连贯性
- 减少重复说明的次数
- 增强个性化服务能力

### 场景二：任务进度跟踪

**描述**：用户在多轮对话中描述自己的目标和进展，系统能够记住这些信息并适时提供协助。

**用户工作流**：
1. 用户说明目标："本周要完成 Agent 项目搭建"
2. 系统提取为 TASK 类型记忆
3. 用户在不同会话中继续讨论相关任务
4. 系统自动提供与该任务相关的建议和帮助

**价值体现**：
- 支持长期任务的连续性
- 提供上下文相关的智能建议
- 增强系统的主动服务能力

### 场景三：背景信息利用

**描述**：用户分享自己的背景信息，系统能够记住这些事实并在适当的场景中利用。

**用户工作流**：
1. 用户提及： "我是做 Java 开发的，主要使用 Spring 框架"
2. 系统提取为 FACT 类型记忆
3. 用户后续询问技术问题时，系统优先推荐 Java/Spring 相关方案
4. 系统基于用户的技术栈提供更有针对性的建议

**价值体现**：
- 提高建议的针对性
- 增强技术支持的个性化
- 优化问题解答的效率

### 场景四：跨会话的上下文保持

**描述**：用户在不同会话之间进行知识讨论，系统能够记住之前讨论的重点。

**用户工作流**：
1. 用户讨论了分布式系统的 CAP 理论
2. 系统提取 EPISODIC 类型记忆
3. 用户开始新的会话，继续讨论一致性算法
4. 系统自动回忆起之前讨论的 CAP 理论背景
5. 系统结合上下文提供更连贯的解释

**价值体现**：
- 保持知识学习的连续性
- 支持深度技术讨论
- 增强理解的连贯性

## 不抽取的场景

为保证记忆质量，系统明确不提取以下类型的信息：

### 一次性操作/命令

- 示例："调用子 agent 查看 user 目录下的文件"
- 示例："运行脚本 X", "ls/cd/cat/npm/pip/install"
- 原因：这些操作对后续对话没有复用价值

### 临时数据或结论

- 示例：仅与当轮问题相关的临时细节
- 原因：后续复用价值不明确，会污染记忆空间

### 隐私或敏感信息

- 示例：身份证号、银行卡、精确住址、电话号码
- 示例：密钥、token、密码
- 原因：涉及用户隐私和安全风险

## 功能特性

### 自动抽取

- **触发时机**：每轮对话结束后自动触发
- **抽取源**：基于用户当轮发言内容
- **评估机制**：通过 LLM 进行价值判断和重要性评分
- **阈值策略**：仅保留 importance ≥ 0.8 的记忆（EPISODIC 类型更严格，需 ≥ 0.9）

### 异步处理

- **处理方式**：使用异步任务执行器（memoryTaskExecutor）
- **性能优化**：不影响主对话流程的响应速度
- **错误处理**：抽取失败不影响正常对话

### 向量化存储

- **嵌入模型**：使用用户专属的嵌入配置
- **元数据关联**：向量中包含 user_id、item_id、type、tags、status 等信息
- **检索效率**：支持高效的语义相似度检索

### 用户隔离

- **数据隔离**：每个用户的记忆完全隔离
- **检索隔离**：检索时仅召回本用户的记忆
- **权限控制**：通过 user_id 实现严格的多租户隔离

## 数据模型

### 记忆条目（MemoryItem）

**核心字段**：
- `id`：记忆条目唯一标识（UUID）
- `user_id`：归属用户ID
- `type`：记忆类型（PROFILE/TASK/FACT/EPISODIC）
- `text`：记忆文本内容
- `data`：结构化数据（JSONB）
- `importance`：重要性评分（0.0-1.0）
- `tags`：标签列表
- `source_session_id`：来源会话ID
- `dedupe_hash`：去重哈希值
- `status`：状态（1=active, 0=archived）

### 候选记忆（CandidateMemory）

**用途**：记忆抽取器的输出结构
- `type`：记忆类型
- `text`：记忆文本
- `importance`：重要性评分
- `tags`：标签列表
- `data`：结构化数据

### 检索结果（MemoryResult）

**用途**：记忆检索的返回结构
- `itemId`：记忆条目ID
- `type`：记忆类型
- `text`：记忆文本
- `importance`：重要性评分
- `tags`：标签列表
- `score`：综合评分（相似度与重要性的加权和）


## 接口定义

### 查询记忆列表

**接口**：`GET /api/portal/memory/list`

**请求参数**：
```json
{
  "page": 1,
  "pageSize": 20,
  "type": "PROFILE"  // 可选
}
```

**响应数据**：
```json
{
  "code": 200,
  "data": {
    "records": [
      {
        "id": "uuid",
        "type": "PROFILE",
        "text": "用户偏好简体中文回答",
        "importance": 0.9,
        "tags": ["preference"],
        "createdAt": "2025-01-15T10:00:00Z",
        "updatedAt": "2025-01-15T10:00:00Z"
      }
    ],
    "total": 100,
    "size": 20,
    "current": 1
  }
}
```

### 手动创建记忆

**接口**：`POST /api/portal/memory/create`

**请求参数**：
```json
{
  "type": "PROFILE",
  "text": "用户偏好简体中文回答",
  "importance": 0.9,
  "tags": ["preference"],
  "data": {}
}
```

**响应数据**：
```json
{
  "code": 200,
  "data": ["uuid"]
}
```

### 删除记忆

**接口**：`DELETE /api/portal/memory/delete/{itemId}`

**响应数据**：
```json
{
  "code": 200,
  "data": true
}
```

## 性能指标

### 存储性能

- 抽取响应时间：< 5秒（异步处理）
- 向量化入库时间：< 2秒单条记忆
- 去重查询时间：< 100ms

### 检索性能

- 相似度检索延迟：< 500ms（Top 16）
- 加权排序时间：< 50ms
- 状态过滤时间：< 50ms

### 容量指标

- 单用户最大记忆数：建议 < 1000 条
- 记忆文本最大长度：5000 字符
- 标签数量限制：建议 < 10 个
- 数据字段大小限制：建议 < 10KB

## 安全与隐私

### 数据隔离

- 严格的多租户隔离机制
- 检索时的用户级过滤
- 禁止跨用户数据访问

### 隐私保护

- 隐私信息识别与过滤
- 敏感信息不抽取
- 支持记忆的归档删除

### 审计追踪

- 记忆来源会话追踪
- 创建和更新时间记录
- 操作日志记录（可扩展）
